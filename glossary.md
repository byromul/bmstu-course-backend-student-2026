Краткие определения сгруппированы по лекциям. Английская форма помогает найти термин в документации.

## Лекция 1 — запуск, Python, структура программы и Git

| Русская форма | Английская форма | Краткое определение |
| --- | --- | --- |
| Учебный проект | course project | Отдельно запускаемый и проверяемый результат нескольких домашних работ; курс создаёт `console-quest` на HW01–HW04 и независимый `django-quest` на HW05–HW08. |
| Рабочая версия | working version | Запускаемое состояние проекта с небольшим законченным изменением; проверенность этого изменения указывается отдельно. |
| Сцена | scene | Одно состояние игрового мира с описанием происходящего и доступными игроку действиями. |
| Вариант выбора | choice | Одно доступное действие игрока с текстом и идентификатором следующей сцены. |
| Терминал | terminal | Текстовый интерфейс для запуска команд и чтения сообщений программ. |
| Командная оболочка | shell | Программа, которая разбирает введённую команду и выполняет её; в лекции 1 используется Bash. |
| Команда | command | Инструкция командной оболочке; при запуске программы включает её имя и аргументы. |
| Аргумент команды | command argument | Отдельное значение после имени программы, которое задаёт файл, данные или режим работы. |
| Процесс | process | Конкретное выполнение программы от запуска до завершения. |
| Путь | path | Адрес файла или каталога; абсолютный путь начинается от корня системы, относительный — от текущего каталога. |
| Текущий каталог | current working directory | Каталог, относительно которого процесс вычисляет относительные пути. |
| Домашний каталог | home directory | Личный каталог текущего пользователя; знак `~` в начале пути сокращённо обозначает его во многих командных оболочках. |
| Стандартный ввод | standard input | Поток, из которого программа читает данные; источником может быть клавиатура, файл или другая программа. |
| Стандартный вывод | standard output | Канал обычного результата программы. |
| Поток данных | data stream | Последовательность данных, которые программа читает или записывает по мере работы. |
| Стандартный поток ошибок | standard error | Отдельный поток диагностических сообщений программы. |
| Конвейер команд | command pipeline | Соединение команд через `\|` (pipe), при котором стандартный вывод команды слева передаётся на стандартный ввод команды справа. |
| Код завершения | exit code | Целое число, которым процесс сообщает успешный или неуспешный итог. |
| Выражение | expression | Синтаксическая конструкция языка программирования, вычисление которой даёт значение. |
| Литерал | literal | Запись значения прямо в исходном коде, например `12` или `"Лина"`. В Python литерал является простейшим выражением: его вычисление даёт записанное значение. |
| Переменная | variable | Имя, связанное со значением (именованная ссылка на объект). Присваивание создаёт эту связь или изменяет её, перепривязывая имя к другому значению; в каждый момент связанное имя ссылается ровно на одно значение. |
| Тип | type | Характеристика значения, которая определяет, какие операции с ним допустимы и как они выполняются. В Python тип принадлежит самому объекту (значению), а не имени. |
| Аннотация типа | type annotation | Синтаксическая запись ожидаемого типа поля, параметра или возвращаемого значения; сама по себе не проверяет значение во время выполнения. |
| `None` | `None` | Единственное значение типа `NoneType`, которое обозначает отсутствие значения. |
| Список | list | Изменяемая упорядоченная последовательность значений с индексами от нуля. |
| Кортеж | tuple | Неизменяемая упорядоченная последовательность значений; запись `()` создаёт пустой кортеж. |
| Словарь | dictionary | Изменяемое соответствие уникальных ключей значениям. |
| Ветвление | conditional branching | Выбор последовательности действий по результату условия. |
| Цикл | loop | Повторение блока команд по элементам или пока условие истинно. |
| Функция | function | Объект, который можно вызвать с аргументами, чтобы выполнить определённое действие и получить результат. |
| Возвращаемое значение | return value | Результат вызова функции, переданный инструкцией `return`; если выполнение дошло до конца функции без явного возврата, результатом будет `None`. |
| Исключение | exception | Сигнал о ситуации, которую обычный ход программы обработать не смог. |
| `ValueError` | `ValueError` | Встроенное исключение Python для неподходящего значения. |
| Модуль | module | Самостоятельная часть Python-программы, которую можно импортировать; в примерах курса хранится в файле с расширением `.py`. |
| Импорт | import | Подключение модуля или имени из него к текущему файлу. |
| Пакет Python | Python package | Набор связанных модулей, которые импортируются под общим именем, например `client.domain`. |
| Обычный пакет Python | regular Python package | Пакет, каталог которого содержит `__init__.py`; при первом импорте пакета Python выполняет этот файл. |
| Пакет пространства имён (namespace package) | namespace package | Пакет без общего `__init__.py`, части которого Python может объединить из нескольких каталогов поиска. |
| `__init__.py` | `__init__.py` | Файл, который явно отмечает каталог как обычный пакет Python; может быть пустым. |
| Точка входа | entry point | Место, откуда начинается прикладной сценарий запуска программы. |
| Виртуальное окружение | virtual environment | Отдельный каталог с выбранным Python и пакетами одного проекта. |
| Зависимость | dependency | Внешний пакет, устанавливаемый отдельно от исходного кода проекта. |
| Файл зависимостей для pip | pip requirements file | Текстовый перечень пакетов и параметров установки; `requirements.txt` — распространённое, но не обязательное имя. |
| Lock-файл | lock file | Файл проекта с выбранными точными версиями для повторяемой установки; формат и полноту задают инструмент и правила проекта. |
| Зафиксированная версия | pinned version | Точная проверенная версия зависимости, записанная в файле проекта. |
| Обратная совместимость | backward compatibility | Способность обновлённой зависимости сохранять работу кода, написанного для предыдущего интерфейса. |
| Класс | class | Определение общей структуры и поведения будущих экземпляров; это не один конкретный игровой объект. |
| Экземпляр | instance | Конкретное значение, созданное по классу и хранящее собственное состояние. |
| Атрибут | attribute | Именованное значение класса или экземпляра, доступное через точку; принадлежность классу или экземпляру уточняется в конкретном примере. |
| Метод | method | Функция класса, которая при вызове через экземпляр получает этот экземпляр первым аргументом. |
| `__init__` | `__init__` | Метод инициализации экземпляра, вызываемый после его создания для задания начального состояния. |
| `self` | `self` | Принятое имя первого параметра метода экземпляра. |
| Декоратор | decorator | Вызываемый объект, который получает функцию или класс и возвращает объект, используемый вместо исходного. |
| `@dataclass` | `@dataclass` | Декоратор стандартной библиотеки, который по объявленным полям создаёт для класса инициализацию и другие служебные методы. |
| Предметная модель | domain model | Часть программы, которая выражает понятия и правила решаемой задачи и не содержит деталей ввода-вывода, отображения и хранения. |
| Многомодульная программа | multi-module program | Программа, исходный код которой разделён между несколькими модулями, связанными импортами и вызовами. |
| Git | Git | Система управления версиями, которая сохраняет снимки состояния файлов и связи между ними. |
| Репозиторий | repository | Рабочие файлы проекта вместе с данными Git, где хранится история изменений. |
| Рабочее дерево | working tree | Файлы текущей версии проекта, которые разработчик читает и изменяет. |
| Индекс Git | Git index | Подготовленное дерево файлов следующего коммита, включая уже отслеживаемые файлы без новых изменений. |
| `.gitignore` | `.gitignore` | Файл правил для неотслеживаемых файлов и каталогов, которые Git скрывает из обычного вывода `status` и не добавляет по общему шаблону; правило не удаляет уже отслеживаемый файл. |
| Снимок | snapshot | Сохранённое состояние дерева проекта на момент коммита. Git строит дерево из индекса и повторно использует уже записанные объекты для неизменившихся данных. В снимок попадает только подготовленное в индексе. |
| Коммит | commit | Запись, сохраняющая снимок дерева из индекса, автора, время, сообщение и ссылки на родительские коммиты. |
| Хеш коммита | commit hash | Вычисленный по содержимому коммита идентификатор; содержимое включает ссылки на родительские коммиты, если они есть. |
| Тег Git | Git tag | Осмысленное имя выбранного коммита, которое Git не передвигает автоматически при появлении новых коммитов. |
| История Git | Git history | Совокупность связанных коммитов, по которым можно восстановить сохранённые состояния проекта и проследить изменения. |
| Ветка Git | Git branch | Подвижное имя, указывающее на последний коммит отдельной линии разработки. |
| Слияние | merge | Операция Git, которая объединяет изменения и историю указанной ветки с текущей веткой. |
| Удалённый репозиторий | remote repository | Другой репозиторий для обмена историей, расположенный на сервере или в отдельном локальном каталоге. |
| Fast-forward | fast-forward | Обновление ветки простым перемещением её указателя вперёд, когда локальная и полученная истории не расходятся. |
| Флаг `--ff-only` | `--ff-only` flag | Аргумент `git pull`, который разрешает только fast-forward и останавливает команду при расходящихся историях. |

## Лекция 2 — данные, тесты, стиль и диагностика

| Русская форма | Английская форма | Краткое определение |
| --- | --- | --- |
| Автоматический тест | automated test | Код, который создаёт известные данные, вызывает поведение и сравнивает результат с ожиданием. |
| Разработка через тестирование (TDD) | test-driven development (TDD) | Рабочий цикл «падающий тест → минимальная реализация → успешный тест → улучшение структуры». |
| Arrange | Arrange | Часть теста, которая подготавливает воспроизводимые исходные данные и зависимости. |
| Act | Act | Часть теста, которая выполняет одно проверяемое действие. |
| Assert | Assert | Часть теста, которая сравнивает наблюдаемый результат с ожидаемым. |
| Arrange–Act–Assert (AAA) | Arrange–Act–Assert (AAA) | Структура теста «подготовить данные → выполнить одно действие → проверить результат». |
| JSON | JavaScript Object Notation (JSON) | JavaScript Object Notation — текстовый формат данных с объектами, массивами, строками, числами, логическими значениями и `null`. |
| JSON-объект | JSON object | Набор пар «строковое имя — значение», заключённый в фигурные скобки. |
| JSON-массив | JSON array | Упорядоченная последовательность значений, заключённая в квадратные скобки. |
| JSON-скаляр | JSON scalar | Одно простое значение JSON: строка, число, логическое значение или `null`. |
| YAML | YAML Ain’t Markup Language (YAML) | Текстовый формат данных. Вложенные элементы сдвигают вправо отступами, показывая их подчинение; отступы — главное, но не единственное средство записи вложенности. |
| Отображение YAML | YAML mapping | Набор пар «ключ — значение», который описывает объект с именованными полями. |
| Последовательность YAML | YAML sequence | Упорядоченный список элементов. Каждый элемент начинается с новой строки с маркера `- ` (дефис и пробел); содержимое на той же строке или с отступом ниже относится к этому элементу. |
| Сериализация | serialization | Преобразование данных программы в формат для хранения или передачи. |
| Десериализация | deserialization | Преобразование сохранённого или полученного представления обратно в данные программы. |
| Состояние партии | game state | Изменяемые данные конкретного прохождения: текущая сцена, имя и характеристики персонажа; Bearer-токен в них не входит. |
| Атомарная запись файла | atomic file write | Замена целевого файла полностью подготовленным временным файлом, которая не оставляет частично записанное новое содержимое. |
| Схема данных | data schema | Машиночитаемое описание допустимой структуры, типов и ограничений данных. |
| JSON Schema | JSON Schema | Формат машиночитаемой схемы для JSON-документов, который описывает ожидаемые типы, обязательные поля и ограничения значений. |
| Регрессионный тест | regression test | Тест, который сохраняет уже подтверждённое поведение при следующих изменениях. |
| Контекстный менеджер | context manager | Объект, который выполняет подготовку перед блоком `with` и завершение после него. |
| Позитивный тест | positive test | Проверка ожидаемого успешного поведения на корректных входных данных. |
| Негативный тест | negative test | Проверка ожидаемого отказа или ошибки на некорректных данных либо запрещённом действии. |
| Стек вызовов | call stack | Структура из незавершённых вызовов: новый вызов кладёт наверх свои данные, завершение снимает верхние. |
| Трассировка стека | stack trace | Список активных вызовов от точки запуска до места ошибки, который Python выводит при необработанном исключении; показывает имена файлов, номера строк и функции. |
| Журналирование | logging | Запись событий выполнения программы с уровнем и полезным контекстом; в индустрии чаще используется слово «логирование». |
| Модуль logging | logging module | Модуль стандартной библиотеки Python для настройки и записи событий; подключается через import logging. |
| Логгер | logger | Объект, через который программа отправляет сообщения с выбранным уровнем важности. |
| Прикладной лог | application log | Записи приложения о значимых событиях выполнения с безопасным контекстом. |
| Уровень сообщения | log level | Категория важности записи лога, например `DEBUG`, `INFO`, `WARNING` или `ERROR`. |
| PEP 8 | PEP 8 | Python Enhancement Proposal 8 — руководство по стилю кода Python. |
| Линтер | linter | Инструмент, который статически ищет выбранные проблемы в исходном коде. |
| Форматтер | formatter | Инструмент, который приводит оформление кода к общей форме. |
| Ruff | Ruff | Используемый в курсе инструмент проверки и форматирования Python-кода. |

## Лекция 3 — клиент, сервер, HTTP и контейнеры

| Русская форма | Английская форма | Краткое определение |
| --- | --- | --- |
| Порт | port | Числовой адрес программы на устройстве, по которому операционная система направляет сетевое соединение. |
| Переменная окружения | environment variable | Именованная текстовая настройка, которую процесс получает извне. |
| Словарное включение | dictionary comprehension | Выражение Python, которое строит словарь из перебираемых элементов по правилу формирования ключа и значения. |
| Форматированная строка (f-string) | formatted string literal (f-string) | Строковый литерал Python с префиксом `f`, который подставляет значения выражений из фигурных скобок. |
| SSH | Secure Shell (SSH) | Secure Shell — протокол защищённого удалённого доступа к серверу. |
| Отпечаток ключа | key fingerprint | Короткое вычисляемое представление открытого ключа сервера для сверки при первом соединении. |
| Открытый ключ | public key | Часть пары ключей, которую можно передать администратору для настройки доступа. |
| Закрытый ключ | private key | Секретная часть пары ключей, которая остаётся на устройстве владельца и не передаётся никогда и никому. |
| `known_hosts` | `known_hosts` | Файл пользователя `~/.ssh/known_hosts`, в котором SSH хранит проверенные открытые ключи серверов. |
| `rg` | `rg` | Команда инструмента ripgrep для поиска строк по тексту или регулярному выражению. |
| Vim | Vim | Терминальный текстовый редактор с отдельными режимами команд и вставки. |
| Клиент | client | Программа, которая отправляет запрос серверу и использует его ответ. |
| Сервер | server | Программа, которая принимает запрос, выполняет обработку и возвращает ответ. |
| HTTP | Hypertext Transfer Protocol (HTTP) | Hypertext Transfer Protocol — протокол обмена запросами и ответами между клиентом и сервером. |
| URL | Uniform Resource Locator (URL) | Uniform Resource Locator — адрес ресурса, включающий схему, узел, необязательный порт и путь. |
| Метод HTTP | HTTP method | Часть запроса, которая задаёт требуемую операцию, например `GET` или `POST`. |
| HTTP-запрос | HTTP request | Сообщение клиента с методом, путём, заголовками и возможным телом. |
| HTTP-ответ | HTTP response | Сообщение сервера со статусом, заголовками и возможным телом. |
| Код состояния | status code | Трёхзначное число, которое кратко сообщает результат обработки HTTP-запроса. |
| Заголовок HTTP | HTTP header | Именованное поле метаданных запроса или ответа. |
| `Content-Type` | `Content-Type` | Заголовок, который указывает формат тела сообщения. |
| Инструменты разработчика браузера | browser developer tools | Встроенная панель браузера для наблюдения страницы, консоли и сетевых запросов; HTTP-обмен виден на вкладке Network. |
| curl | curl | Консольный инструмент передачи данных по URL, используемый в курсе для явных HTTP-запросов. |
| `jq` | `jq` | Консольный инструмент разбора, форматирования и фильтрации JSON. |
| Образ контейнера | container image | Неизменяемый шаблон файлов и настроек для создания контейнера. |
| Контейнер | container | Изолированный процесс с файловой системой и настройками, созданный из образа. |
| `Dockerfile` | `Dockerfile` | Файл инструкций для сборки образа контейнера. |
| Compose | Compose | Средство описания и согласованного запуска нескольких сервисов. |

## Лекция 4 — база данных и контракт программного интерфейса

| Русская форма | Английская форма | Краткое определение |
| --- | --- | --- |
| Реляционная база данных | relational database | База, в которой данные представлены связанными таблицами с ограничениями. |
| SQLite | SQLite | Встраиваемая реляционная система управления базами данных, которая хранит базу в файле. |
| Таблица | table | Именованная структура строк с общим набором столбцов. |
| Строка таблицы | table row | Одна запись с конкретными значениями столбцов. |
| Столбец | column | Именованное поле таблицы с заданным назначением и типом. |
| Первичный ключ | primary key | Значение, которое однозначно идентифицирует строку таблицы. |
| Внешний ключ | foreign key | Поле, которое ссылается на строку другой таблицы. |
| Связь «один ко многим» | one-to-many relationship | Отношение, при котором одной строке первой таблицы соответствуют несколько строк второй. |
| Ограничение базы данных | database constraint | Правило, которому должны соответствовать сохраняемые данные. |
| SQL | Structured Query Language (SQL) | Structured Query Language — язык запросов и изменений реляционных данных. |
| `SELECT` | `SELECT` | Инструкция SQL для чтения выбранных строк и столбцов без изменения данных. |
| Схема базы данных | database schema | Набор таблиц, столбцов, типов, ключей и ограничений, который задаёт структуру хранимых данных. |
| JOIN | JOIN | Часть SQL-запроса, которая сопоставляет строки нескольких таблиц по явному условию связи. |
| API | Application Programming Interface (API) | Application Programming Interface — соглашение о том, как одна программа обращается к возможностям другой. |
| JSON API | JSON API | Программный интерфейс, который передаёт данные запросов и ответов в JSON. |
| API-first | API-first | Подход, при котором контракт программного интерфейса задаётся и проверяется до реализации. |
| OpenAPI 3.1 | OpenAPI 3.1 | Машиночитаемый формат описания операций HTTP-интерфейса, параметров, тел, ответов и схем. |
| DDL | Data Definition Language (DDL) | Часть SQL для создания и изменения структуры базы: таблиц, столбцов, ключей и ограничений. |
| DML | Data Manipulation Language (DML) | Часть SQL для чтения и изменения строк созданных таблиц, например `SELECT`, `INSERT`, `UPDATE` и `DELETE`. |
| CORS | Cross-Origin Resource Sharing (CORS) | Правило браузера и HTTP-заголовков, по которому сервер разрешает странице с одного источника читать ответ с другого. |
| Swagger UI | Swagger UI | Веб-интерфейс для чтения OpenAPI и выполнения пробных запросов. |
| Аутентификация | authentication | Проверка того, от имени какого пользователя выполняется запрос. |
| Авторизация | authorization | Проверка того, разрешено ли установленному пользователю выполнить действие. |
| Сессия | session | Серверное состояние входа, связанное с конкретным пользователем и сохраняемое между запросами. |
| Cookie | cookie | Небольшое значение, которое браузер сохраняет для сайта и отправляет обратно в подходящих запросах; при сессионном входе обычно несёт идентификатор сессии. |
| Basic | Basic authentication | Схема HTTP-аутентификации, которая передаёт учётные данные по правилам протокола и требует защищённого канала. |
| API key | API key | Выданный приложению ключ, который сервис принимает в заранее определённом месте запроса. |
| GraphQL | GraphQL | Подход к API с языком запросов, в котором клиент описывает нужную структуру данных. |
| JSON-RPC | JSON-RPC | Протокол удалённых вызовов процедур с сообщениями JSON. |
| gRPC | gRPC | Средство удалённых вызовов с контрактами сервисов и двоичным транспортом. |
| Protocol Buffers | Protocol Buffers | Формат и язык описания структурированных сообщений, используемый в том числе с gRPC. |
