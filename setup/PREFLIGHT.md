# Подготовка к первой практике

Цель подготовки — проверить базовую среду до создания первого продукта: Python 3.14.7, создание временного виртуального окружения, UTF-8 и локальный Git-коммит. Готового `console-quest`, проектной `.venv` и установленных пакетов на этом шаге ещё нет. Podman или Docker и SSH-подключение проверяются отдельно перед лекцией 3 и не блокируют первую домашнюю работу.

Преподаватель публикует эту инструкцию и [конспект лекции 1](../student/handouts/L01.md) не позднее чем за пять дней до лекции. Полный текст инструментальной проверки передайте в канал `setup` не позднее чем за 48 часов, чтобы неизвестная блокировка получила раннюю консультацию.

Если шаг не проходит, не скрывайте сообщение и не переустанавливайте всё подряд. Скопируйте команду, полный текст результата и название операционной системы в постоянный канал `setup`. Не публикуйте пароль, закрытый SSH-ключ, токен или содержимое `.env`. Преподаватель подтверждает замеченное сообщение ответом `Принято преподавателем: <номер вопроса>`.

## 1. Python 3.14.7

Во всех командах курса после активации окружения используется имя `python`. До создания окружения команда зависит от операционной системы.

### Windows 10 или 11

1. Установите выпуск Python 3.14.7 с [официальной страницы Python](https://www.python.org/downloads/release/python-3147/). Разрешите установщику добавить команду запуска Python.
2. Откройте новое окно PowerShell.
3. Проверьте версию:

```powershell
py -3.14 --version
```

Ожидается `Python 3.14.7`. Если система открывает Microsoft Store или показывает другую версию, приложите этот вывод к обращению `setup`.

### macOS

1. Установите универсальный пакет Python 3.14.7 с [официальной страницы Python](https://www.python.org/downloads/release/python-3147/).
2. Откройте новое окно Terminal.
3. Проверьте версию:

```bash
python3.14 --version
```

Ожидается `Python 3.14.7`. Не заменяйте системный Python macOS и не используйте `sudo pip`.

### Linux

Сначала проверьте, предоставляет ли ваша система точный выпуск отдельной командой:

```bash
python3.14 --version
```

Если результат равен `Python 3.14.7`, переходите к Git. Не заменяйте `/usr/bin/python3`: от него могут зависеть системные инструменты.

#### Проверенная последовательность для Ubuntu 24.04 LTS

Последовательность ниже воспроизведена 9 сентября 2026 года в чистом Ubuntu 24.04 LTS на ARM64: контрольная сумма архива совпала, установленный интерпретатор и созданная им `.venv` показали `Python 3.14.7`, а `pip` запустился. Команды используют официальный архив Python и рекомендации по зависимостям сборки CPython. Для выполнения нужны `sudo`, доступ в интернет и свободное место для исходников и сборки.

Установите инструменты и библиотеки сборки:

```bash
sudo apt update
sudo apt install --no-install-recommends build-essential pkg-config ca-certificates curl xz-utils \
  libbz2-dev libffi-dev libgdbm-dev liblzma-dev libncurses-dev libreadline-dev \
  libsqlite3-dev libssl-dev tk-dev uuid-dev zlib1g-dev
```

Скачайте официальный архив, проверьте его контрольную сумму и распакуйте:

```bash
cd /tmp
curl -fsSLO https://www.python.org/ftp/python/3.14.7/Python-3.14.7.tar.xz
printf '%s  %s\n' \
  '3b48dac8fb59f62eaa67ac83c1eb12bda1b7a08406dd286e252c11a66be27f81' \
  'Python-3.14.7.tar.xz' | sha256sum -c -
tar -xf Python-3.14.7.tar.xz
cd Python-3.14.7
```

Строка проверки должна быть `Python-3.14.7.tar.xz: OK`. После неё соберите интерпретатор в отдельный каталог, не заменяя системный Python:

```bash
./configure --prefix=/opt/python-3.14.7 --with-ensurepip=install
make -j2
sudo make install
/opt/python-3.14.7/bin/python3.14 --version
```

Ожидается `Python 3.14.7`. В разделе создания окружения используйте именно `/opt/python-3.14.7/bin/python3.14 -m venv .venv`.

Если у вас нет `sudo`, используется другой выпуск Linux либо любая команда выше завершилась не ожидаемой строкой, остановитесь и запросите управляемый резерв в `setup`. До срока подготовки преподаватель назначает раннюю техническую консультацию или предоставляет резервный университетский компьютер с Ubuntu 24.04 LTS, на котором проектная предварительная проверка уже проходит. В обращении приложите первую ошибку и вывод:

```bash
cat /etc/os-release
python3 --version
```

## 2. Git и подпись коммита

Установите Git проверенным способом для своей системы:

- Windows 10 или 11 — загрузите установщик с [официальной страницы Git для Windows](https://git-scm.com/install/windows) либо выполните указанную там команду `winget`;
- macOS — выполните `xcode-select --install` или выберите другой актуальный способ на [официальной странице Git для macOS](https://git-scm.com/install/mac);
- Debian или Ubuntu — выполните `sudo apt install git`; Fedora — `sudo dnf install git`; команды для других систем приведены на [официальной странице Git для Linux](https://git-scm.com/install/linux).

Откройте новое окно терминала и выполните:

```bash
git --version
git config --global user.name "Имя Фамилия"
git config --global user.email "ваш-адрес@example.org"
git config --get user.name
git config --get user.email
```

В двух последних строках должны появиться ваши имя и адрес. Укажите адрес, который разрешено сохранять в истории учебного репозитория.

## 3. Комплект курса без готового продукта

Скачайте и распакуйте опубликованный комплект курса в отдельный каталог. В его корне должен находиться файл `scripts/preflight.py`. На этом шаге не клонируйте и не создавайте `console-quest`: первый продукт начнётся с пустого каталога уже в HW01.

Проверьте текущий каталог и наличие сценария:

```bash
python -c "from pathlib import Path; print(Path.cwd()); print(Path('scripts/preflight.py').is_file())"
```

Последняя строка должна быть `True`. Если получено `False`, перейдите в корень распакованного комплекта или скачайте его заново из опубликованного источника. Не копируйте `preflight.py` из чужого продукта и не создавайте отсутствующий файл вручную.

## 4. Редактор и пробный каталог

Создайте вне будущих продуктов пустой каталог `course-editor-check`, откройте его в редакторе и вручную создайте файл `editor-check.txt` с единственной строкой `Проверка UTF-8`. Затем из этого каталога выполните:

```bash
python -c "from pathlib import Path; print(Path('editor-check.txt').read_text(encoding='utf-8'))"
git init -b main
git status --short
```

Python должен напечатать `Проверка UTF-8`, а Git — строку `?? editor-check.txt`. После наблюдения удалите весь пробный каталог обычными средствами файловой системы. Эта ручная проверка подтверждает работу редактора; автоматический сценарий ниже независимо проверяет создание временного окружения и коммита.

## 5. Автоматическая предварительная проверка

Вернитесь в корень распакованного комплекта курса и запустите сценарий точной версией Python 3.14.7:

```bash
python scripts/preflight.py
```

Если на вашей системе точный интерпретатор вызывается иначе, замените только имя программы: на Windows используйте `py -3.14 scripts/preflight.py`, а на macOS или Linux — `python3.14 scripts/preflight.py`. Активировать проектное окружение и устанавливать пакеты не нужно.

Сценарий выполняет изолированный пробный маршрут:

1. Проверяет точную версию запущенного Python;
2. Создаёт во временном каталоге новое виртуальное окружение;
3. Записывает и читает русскую строку в UTF-8 интерпретатором этого окружения;
4. Проверяет наличие Git, `user.name` и `user.email`;
5. Создаёт новый временный Git-репозиторий, файл и коммит;
6. Удаляет временный каталог после завершения.

Последняя строка успешного запуска:

```text
ПРЕДВАРИТЕЛЬНАЯ ПРОВЕРКА ПРОЙДЕНА: Python 3.14.7, временное окружение, UTF-8 и Git
```

Сохраните полный текст запуска. Проверка не читает продукт, не меняет комплект курса и не обращается к сети.

## Восстановление по первой ошибке

1. `нужен Python 3.14.7` — вернитесь к разделу своей операционной системы и повторите сценарий точным интерпретатором;
2. ошибка команды `venv` — проверьте, что установка Python содержит модуль `venv`, и приложите полный вывод в канал `setup`;
3. `временное окружение не воспроизвело запись и чтение UTF-8` — приложите полный вывод, название операционной системы и используемый терминал в канал `setup`;
4. `Git не найден в PATH` — установите Git по разделу 2 и откройте новое окно терминала;
5. `не настроен Git: задайте user.name` или `user.email` — выполните соответствующую команду `git config --global` из раздела 2;
6. ошибка временного коммита — сохраните полный вывод и значения `git config --get user.name` и `git config --get user.email`, не публикуя секреты.

После исправления повторите ту же команду запуска. Обращение до опубликованного срока получает ответ или назначение ранней технической консультации до первой домашней работы. Техническая блокировка, зафиксированная полным выводом, не превращается в требование угадывать причину самостоятельно.

# Подготовка к лекции 3

Эта часть выполняется позже, по напоминанию преподавателя. Выберите один доступный движок контейнеров и заранее загрузите точный проверочный образ.

Podman:

```bash
podman pull docker.io/library/python:3.14.7-slim
python scripts/preflight.py --profile containers
```

Docker:

```bash
docker pull docker.io/library/python:3.14.7-slim
python scripts/preflight.py --profile containers
```

Не запускайте оба варианта: нужен один работающий движок. Контейнерный профиль повторяет базовые проверки, убеждается, что образ уже загружен, и выполняет в нём `python --version`; сценарий намеренно не загружает образ сам и не скрывает сетевую операцию. До лекции 3 преподаватель выдаёт адрес сервера, логин, порт и доверенный отпечаток ключа сервера. Для работы на Windows выполните следующие шаги; для macOS и Linux используйте выданную платформенную инструкцию. Передаётся только открытый ключ; закрытый ключ всегда остаётся на устройстве студента.

## SSH-доступ с Windows к удалённому Linux

SSH-клиент на вашем компьютере устанавливает защищённое соединение с Linux-сервером. Для входа по ключу создаются два разных файла: закрытый ключ остаётся на вашем компьютере, а открытый ключ с расширением `.pub` преподаватель добавляет в вашу учётную запись на сервере. Адрес, логин и порт берите из выданной карточки доступа; значения `student@example.edu` и `22` в примере ниже замените на свои.

### 1. Проверьте SSH-клиент

Откройте новое окно PowerShell и выполните:

```powershell
ssh -V
Get-Command ssh-keygen
```

Первая команда должна показать версию OpenSSH, вторая — найденную программу `ssh-keygen`. Если PowerShell сообщает, что `ssh` или `ssh-keygen` не найдена, откройте «Параметры» Windows, найдите «Дополнительные компоненты», добавьте **OpenSSH Client** и откройте новое окно PowerShell. Для исходящего подключения компонент **OpenSSH Server** на вашем компьютере не требуется. Порядок установки описан в [официальной инструкции Microsoft](https://learn.microsoft.com/en-us/windows-server/administration/openssh/openssh_install_firstuse) (SRC54).

### 2. Создайте личную пару ключей

Создайте каталог для ключей и проверьте, что выбранное имя ещё не занято:

```powershell
New-Item -ItemType Directory -Force -Path "$env:USERPROFILE\.ssh" | Out-Null
Test-Path "$env:USERPROFILE\.ssh\course_ed25519"
Test-Path "$env:USERPROFILE\.ssh\course_ed25519.pub"
```

Ожидается `False` в обеих последних строках. Если хотя бы одна строка показывает `True`, выберите другое имя, например `course_ed25519_2`, и используйте его во всех следующих командах. Не подтверждайте перезапись существующего ключа.

Когда имя свободно, создайте ключи:

```powershell
ssh-keygen -t ed25519 -f "$env:USERPROFILE\.ssh\course_ed25519"
```

Программа дважды запросит фразу доступа для закрытого ключа. Рекомендуется задать непустую фразу и сохранить её в личном менеджере паролей; при вводе символы не отображаются. После создания будут два файла: `course_ed25519` — закрытый ключ, `course_ed25519.pub` — открытый. Подробности о паре ключей приведены в [документации Microsoft](https://learn.microsoft.com/en-us/windows-server/administration/openssh/openssh_keymanagement) (SRC55).

### 3. Передайте только открытый ключ

Выведите содержимое открытого файла:

```powershell
Get-Content "$env:USERPROFILE\.ssh\course_ed25519.pub"
```

Ожидается одна длинная строка, начинающаяся с `ssh-ed25519`. Скопируйте её целиком в Яндекс Форму, указанную преподавателем. Не отправляйте файл без расширения `.pub`, фразу доступа или снимок экрана с содержимым закрытого ключа. Дождитесь подтверждения, что открытый ключ добавлен в вашу учётную запись на сервере.

### 4. Сверьте сервер и войдите

После получения карточки доступа замените в команде логин `student`, адрес `example.edu` и порт `22` на выданные значения:

```powershell
ssh -i "$env:USERPROFILE\.ssh\course_ed25519" -o IdentitiesOnly=yes -p 22 student@example.edu
```

При первом соединении SSH показывает отпечаток ключа сервера вида `SHA256:...`. Сравните всю строку с отпечатком, полученным от преподавателя независимым каналом. Ответьте `yes` только при полном совпадении; если отпечаток отличается или не выдан, остановитесь и обратитесь в канал `setup`. После подтверждения может появиться запрос фразы доступа от вашего закрытого ключа. Введите её локально в PowerShell.

Когда откроется терминал удалённого Linux, выполните команды уже на сервере:

```bash
whoami
exit
```

`whoami` должен показать выданный вам логин, а `exit` возвращает к PowerShell на вашем компьютере. При повторном входе SSH обычно не спрашивает подтверждение того же ключа сервера. Если позже появится предупреждение об изменении ключа сервера, не удаляйте запись из `known_hosts` до выяснения причины у преподавателя.

### Если подключение не удалось

1. `ssh` не найдена — установите **OpenSSH Client** по шагу 1 и откройте новое окно PowerShell;
2. `Permission denied (publickey)` — проверьте логин, путь после `-i` и подтверждение добавления именно вашего открытого ключа на сервер;
3. `Connection timed out` или `Connection refused` — сверьте адрес, порт и доступ к сети, затем передайте полный текст ошибки в канал `setup`;
4. отпечаток сервера отличается от выданного или изменился после успешного входа — прекратите подключение и запросите подтверждение у преподавателя.
