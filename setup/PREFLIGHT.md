# Подготовка среды

Здесь два этапа подготовки. Выполняйте шаги по порядку внутри своего этапа; в разделах с вариантами выбирайте свою операционную систему или один инструмент.

| Когда выполнять | Что подготовить | Чем подтвердить готовность |
|---|---|---|
| До первой лекции | Python 3.14.7, Git, редактор и комплект курса на своём компьютере | Чтение пробного файла и успешный базовый запуск `preflight.py` |
| Перед лекцией 3, по напоминанию преподавателя | Доступ к удалённому Linux и один локальный движок контейнеров | Вход по SSH под своим логином и успешный контейнерный профиль `preflight.py` |

На подготовительном этапе вы проверяете инструменты. Создание `console-quest`, его `.venv` и первых файлов проекта начинается в домашнем задании 1. Распакованный комплект курса и каталог будущего проекта должны быть разными папками.

Преподаватель публикует эту инструкцию и [конспект лекции 1](../student/handouts/L01.md) не позднее чем за пять дней до занятия. Полный текст базовой проверки передайте в канал `setup` не позднее чем за 48 часов до первой лекции. Если шаг не получается, сохраните первую ошибку и обратитесь за помощью по разделу в конце инструкции.

## Этап А. Подготовка к первой лекции

Все действия этого этапа выполняются **на вашем компьютере**. SSH-подключение пока не требуется.

### 1. Откройте терминал своей системы

Терминал — окно, в котором вы вводите команды и читаете ответы программ. Вводите команду целиком, затем нажимайте `Enter`; следующую вводите после завершения предыдущей. Текст внутри блока с ожидаемым результатом вводить не нужно.

- На Windows нажмите `Win`, наберите `PowerShell` и нажмите `Enter`. Используйте обычное окно; права администратора нужны только там, где это явно указано;
- на macOS нажмите `Cmd+Space`, введите `Terminal` и нажмите `Enter`;
- на Linux откройте приложение «Терминал» из меню своей системы.

После установки программы закрывайте прежнее окно терминала и открывайте новое: уже открытое окно может ещё не видеть установленную команду.

### 2. Установите и проверьте Python 3.14.7

Пройдите только подраздел своей системы. Если нужная версия уже установлена, достаточно получить указанный результат проверки.

#### Windows 10 или 11

1. Откройте [страницу Python 3.14.7](https://www.python.org/downloads/release/python-3147/), найдите раздел **Files** и выберите установщик Windows для архитектуры своего компьютера;
2. Запустите скачанный установщик, разрешите установку средства запуска Python и завершите установку;
3. Откройте новое обычное окно PowerShell и выполните:

   ```powershell
   py -3.14 --version
   ```

   Ожидаемый результат:

   ```text
   Python 3.14.7
   ```

Если команда не найдена, открывается Microsoft Store или выводится другая версия, сохраните сообщение и обратитесь в `setup`. Не переходите к последующим проверкам с другим Python.

#### macOS

1. На [странице Python 3.14.7](https://www.python.org/downloads/release/python-3147/) в разделе **Files** скачайте установщик для macOS;
2. Откройте скачанный `.pkg` и завершите установку;
3. Откройте новое окно Terminal и выполните:

   ```bash
   python3.14 --version
   ```

   Ожидаемый результат — `Python 3.14.7`.

Не заменяйте системный Python macOS. Для этой подготовки не требуется `sudo pip`.

#### Linux

В локальном терминале выполните:

```bash
python3.14 --version
```

Если получено `Python 3.14.7`, этот шаг завершён. Если команда отсутствует или версия отличается, используйте [справочный раздел для Ubuntu 24.04 LTS](#справка-установка-python-3147-на-ubuntu-2404-lts) в конце документа либо запросите у преподавателя путь для своей системы. Не заменяйте `/usr/bin/python3`: он может требоваться самой операционной системе.

После установки из справочного раздела Python запускается полным путём `/opt/python-3.14.7/bin/python3.14`. В последующих шагах для него приведён отдельный блок команд.

### 3. Установите Git и задайте данные автора

Git понадобится для сохранения истории проекта. Сначала установите его способом для своей системы:

- на Windows скачайте и запустите установщик с [официальной страницы Git для Windows](https://git-scm.com/install/windows), завершите установку;
- на macOS выполните `xcode-select --install` и дождитесь установки инструментов разработчика либо используйте другой способ с [официальной страницы Git для macOS](https://git-scm.com/install/mac);
- на Debian или Ubuntu выполните `sudo apt install git`, на Fedora — `sudo dnf install git`; для других систем выберите инструкцию на [официальной странице Git для Linux](https://git-scm.com/install/linux).

Откройте новое окно терминала и проверьте:

```bash
git --version
```

В ответ должна появиться строка, начинающаяся с `git version`. Затем задайте свои данные, заменив пример внутри кавычек:

```bash
git config --global user.name "Имя Фамилия"
git config --global user.email "ваш-адрес@example.org"
```

Проверьте сохранённые значения:

```bash
git config --get user.name
git config --get user.email
```

Ожидаются ваше имя и выбранный адрес. Они будут записываться в коммиты; укажите адрес, который разрешено сохранять в истории учебного репозитория. Это данные автора коммитов, а не пароль и не настройка входа на GitHub.

### 4. Подготовьте редактор

Если у вас уже есть редактор, который открывает и сохраняет файлы в UTF-8, используйте его. Ниже действия показаны на примере VS Code; его использование не обязательно.

Если выбрали VS Code:

1. Откройте [страницу загрузки VS Code](https://code.visualstudio.com/download) и выберите свою систему;
2. Установите приложение: на Windows запустите установщик **User Installer**, на macOS распакуйте архив и переместите приложение в **Applications**, на Linux используйте пакет для своего дистрибутива;
3. Запустите VS Code. Пока работайте в локальном окне: индикатора **SSH: …** в левом нижнем углу быть не должно.

Проверка сохранения файла будет на шаге 6, после получения комплекта курса. Расширение Remote - SSH сейчас устанавливать не требуется.

### 5. Скачайте комплект курса и откройте его корневую папку

1. Откройте [репозиторий студенческих материалов](https://github.com/byromul/bmstu-course-backend-student-2026);
2. Нажмите **Code → Download ZIP** и дождитесь загрузки архива;
3. Распакуйте архив обычными средствами системы. На Windows щёлкните архив правой кнопкой и выберите **Извлечь всё…**; на macOS откройте архив двойным щелчком; на Linux используйте команду распаковки в файловом менеджере;
4. Откройте распакованную папку. Найдите уровень, на котором одновременно видны `README.md`, папка `scripts` и папка `setup`. Это корень комплекта; если сначала видна только одна вложенная папка, войдите в неё;
5. Убедитесь, что внутри `scripts` есть файл `preflight.py`. Если его нет, проверьте, что скачали весь архив нужного репозитория, а не отдельную страницу или файл;
6. В редакторе выберите **File → Open Folder…** и откройте именно корневую папку комплекта.

В комплекте уже есть учебные материалы, но это ещё не ваш `console-quest`. Не создавайте в нём каталог первого проекта и не переименовывайте комплект в проект.

### 6. Проверьте создание файла и чтение UTF-8

Эта проверка нужна, чтобы убедиться, что вы умеете создать файл, сохранить его и запустить команду из нужной папки.

1. Через файловый менеджер создайте отдельную пустую папку `course-editor-check`, например в своих «Документах», вне распакованного комплекта и будущего проекта;
2. В редакторе откройте эту папку. В VS Code используйте **File → Open Folder…**;
3. Создайте файл **editor-check.txt**, введите единственную строку `Проверка UTF-8` и сохраните файл сочетанием `Ctrl+S` (`Cmd+S` на macOS). В VS Code кодировка показывается в строке состояния; при необходимости нажмите на неё и выберите **Save with Encoding → UTF-8**;
4. Откройте терминал в этой папке. В VS Code выберите **Terminal → New Terminal**: новое окно терминала должно открыться в папке, выбранной на предыдущем шаге;
5. Выполните команду чтения для своего Python.

На Windows:

```powershell
py -3.14 -c "from pathlib import Path; print(Path('editor-check.txt').read_text(encoding='utf-8'))"
```

На macOS или Linux с командой `python3.14`:

```bash
python3.14 -c "from pathlib import Path; print(Path('editor-check.txt').read_text(encoding='utf-8'))"
```

На Ubuntu после установки Python из справочного раздела:

```bash
/opt/python-3.14.7/bin/python3.14 -c "from pathlib import Path; print(Path('editor-check.txt').read_text(encoding='utf-8'))"
```

Ожидаемый результат:

```text
Проверка UTF-8
```

Если получено `FileNotFoundError`, проверьте имя сохранённого файла и папку терминала. Показать текущую папку можно командой `Get-Location` в PowerShell или `pwd` в Terminal и Linux. Если файл находится в другой папке, откройте правильную папку в редакторе и создайте новый терминал.

В том же пробном каталоге выполните:

```bash
git init -b main
git status --short
```

В выводе последней команды ожидается `?? editor-check.txt`: Git видит созданный файл, но он ещё не включён в историю. Закройте пробную папку в редакторе; после проверки её можно удалить через файловый менеджер. Комплект курса и будущий проект не удаляйте.

### 7. Запустите базовую проверку среды

1. В редакторе снова откройте **корень комплекта курса** со шага 5;
2. Закройте прежний пробный терминал и откройте новый через **Terminal → New Terminal**. Открытие другой папки не переносит уже запущенный терминал в неё;
3. Проверьте наличие сценария: в PowerShell выполните `Get-Item scripts/preflight.py`, на macOS или Linux — `ls scripts/preflight.py`. Если файл не найден, вернитесь к выбору корневой папки на шаге 5;
4. Выполните команду своей системы.

На Windows:

```powershell
py -3.14 scripts/preflight.py
```

На macOS или Linux с командой `python3.14`:

```bash
python3.14 scripts/preflight.py
```

На Ubuntu после установки Python из справочного раздела:

```bash
/opt/python-3.14.7/bin/python3.14 scripts/preflight.py
```

Активировать проектное окружение и устанавливать пакеты для этой проверки не нужно. Сценарий сам создаёт временное окружение и временный репозиторий, проверяет UTF-8 и коммит, затем удаляет временные данные. Файлы будущего проекта ему не нужны, к сети он не обращается.

Последняя строка успешного запуска:

```text
ПРЕДВАРИТЕЛЬНАЯ ПРОВЕРКА ПРОЙДЕНА: Python 3.14.7, временное окружение, UTF-8 и Git
```

Если этой строки нет, найдите первое сообщение `ПРОВЕРКА НЕ ПРОЙДЕНА` и исправьте его причину:

| Сообщение | Следующее действие |
|---|---|
| Нужен Python 3.14.7 | Вернитесь к шагу 2 и запустите проверку тем интерпретатором, версия которого была подтверждена |
| Ошибка команды `venv` | Сохраните полный вывод: установка Python должна поддерживать создание окружений; запросите помощь в `setup` |
| Ошибка записи или чтения UTF-8 | Сохраните полный вывод, название системы и используемого терминала для обращения в `setup` |
| Git не найден в PATH | Завершите установку Git на шаге 3 и откройте новое окно терминала |
| Не настроен `user.name` или `user.email` | Повторите соответствующую команду `git config --global` на шаге 3 |
| Ошибка временного коммита | Сохраните полный вывод и проверьте `git config --get user.name` и `git config --get user.email` |

После исправления повторите **ту же команду запуска** из корня комплекта. Код завершения `0` означает успех, `1` — обнаруженное несоответствие, `2` — ошибку параметров команды.

Этап А завершён, когда:

- пробный файл выводится как `Проверка UTF-8`;
- базовая проверка завершается строкой `ПРЕДВАРИТЕЛЬНАЯ ПРОВЕРКА ПРОЙДЕНА`;
- вы можете открыть материалы курса и передать полный текст проверки в канал `setup`.

До домашнего задания 1 также проверьте, что можете войти в GitHub и открыть страницу создания нового репозитория. Сам репозиторий первого проекта создаётся по инструкции домашнего задания.

## Этап Б. Подготовка к лекции 3

Начинайте этот этап по напоминанию преподавателя после базовой подготовки. Сначала получите данные доступа и проверьте вход на сервер; затем при желании настройте удалённый редактор. Контейнеры проверяются отдельно **на вашем компьютере**.

### 8. Получите данные доступа к серверу

Прежде чем открывать SSH-клиент, получите от преподавателя:

- IP-адрес или доменное имя сервера;
- свой индивидуальный логин;
- пароль, переданный через личный канал;
- порт SSH: обычно `22`, но он может отличаться;
- доверенный отпечаток ключа сервера, например строку, начинающуюся с `SHA256:`;
- сведения о необходимой сети или VPN, если сервер доступен только из учебной сети.

Если чего-то не хватает, запросите данные у преподавателя. Не подставляйте наугад адрес, порт или чужую учётную запись. Данные `alex` и `192.168.1.50` ниже — только условный пример.

### 9. Проверьте вход по SSH из терминала

SSH позволяет выполнять команды на удалённом компьютере. На Windows выберите **один** из вариантов ниже: PowerShell или PuTTY. Для работы из VS Code сначала проверьте вариант с командой `ssh`; отдельная установка PuTTY для него не нужна.

На macOS и Linux команда `ssh` выполняется из обычного локального терминала по той же схеме, что и в подразделе PowerShell. Установка компонента Windows к этим системам не относится.

#### Вариант 1. PowerShell или локальный терминал macOS и Linux

Сначала проверьте, доступен ли SSH-клиент. В локальном терминале выполните:

```bash
ssh -V
```

Ожидается строка с версией OpenSSH. Если команда найдена, переходите к подключению. Если PowerShell сообщает, что команда не найдена, установите компонент Windows:

Откройте PowerShell **от имени администратора** и выполните:

```powershell
Add-WindowsCapability -Online -Name OpenSSH.Client~~~~0.0.1.0
```

После успешной установки откройте новое обычное окно PowerShell и снова выполните `ssh -V`. Команда установки приведена в [документации Microsoft](https://learn.microsoft.com/en-us/windows-server/administration/openssh/openssh_install_firstuse) (SRC54).

Подключение:

1. На Windows откройте обычное окно PowerShell. На macOS или Linux используйте локальный терминал;
2. Выберите команду с учётом выданного порта. Для порта `22`:

   ```powershell
   ssh ЛОГИН@ХОСТ
   ```

   Для другого порта добавьте `-p` с его номером. Например, для `2222`:

   ```powershell
   ssh -p 2222 ЛОГИН@ХОСТ
   ```

   Замените `ЛОГИН` и `ХОСТ` своими данными. При логине `alex` и адресе `192.168.1.50` второй пример станет `ssh -p 2222 alex@192.168.1.50`. Выполните только подходящую вам команду и нажмите `Enter`;
3. При первом подключении появится вопрос `Are you sure you want to continue connecting?`. Сверьте отпечаток `SHA256:...` с полученным от преподавателя. При полном совпадении введите `yes` и нажмите `Enter`. Если отпечаток отличается или не выдан, прекратите подключение и обратитесь к преподавателю;
4. Когда появится `password:`, введите пароль и нажмите `Enter`. Символы и звёздочки не отображаются — это нормально;
5. Выполните `whoami`: сервер должен показать ваш логин. Теперь команды выполняются на сервере;
6. Для отключения введите `exit` и нажмите `Enter`. Вы вернётесь в локальный терминал на своём компьютере.


#### Вариант 2. PuTTY на Windows

Если PuTTY ещё не установлен, откройте [официальный сайт](https://www.puttyssh.org/), перейдите по ссылке загрузки и выберите установщик для Windows и архитектуры своего компьютера. Запустите установщик, завершите установку и найдите PuTTY через меню «Пуск».

1. Запустите PuTTY;
2. В поле **Host Name (or IP address)** введите IP-адрес или доменное имя выданного сервера;
3. В поле **Port** укажите `22` или другой порт, выданный преподавателем, например `2222`;
4. Убедитесь, что в поле **Connection type** выбрано **SSH**;
5. Нажмите **Open** внизу окна;
6. При первом подключении появится **Security Alert**. Сверьте показанный отпечаток ключа с полученным от преподавателя. Только при совпадении нажмите **Accept** или **Да**, чтобы сохранить ключ сервера. Если отпечаток отличается или не выдан, закройте подключение и обратитесь к преподавателю;
7. В открывшейся консоли после приглашения `login as:` введите свой логин, например `alex`, и нажмите `Enter`. Затем введите пароль и снова нажмите `Enter`. При вводе пароля символы и звёздочки не отображаются;
8. Выполните `whoami`: сервер должен показать ваш логин. Теперь команды выполняются на сервере. Для отключения введите `exit` и нажмите `Enter`.

#### Если SSH не подключается

- `Connection timed out` — проверьте адрес, порт, доступность сервера и подключение к VPN, если оно требуется для учебной сети;
- `Connection refused` — сверьте порт; попросите преподавателя проверить, запущена ли SSH-служба на сервере;
- `Permission denied` — проверьте логин, пароль и раскладку клавиатуры. Если сообщение содержит только `publickey` и пароль не запрашивается, попросите преподавателя проверить разрешение входа по паролю;
- отпечаток сервера отличается от выданного или изменился после успешного входа — прекратите подключение и запросите подтверждение у преподавателя.

### 10. При желании подключите VS Code к серверу

Расширение Remote - SSH позволяет открыть папку сервера в VS Code и редактировать её файлы. Для этого способа на компьютере должен работать совместимый с OpenSSH клиент: на Windows сначала проверьте команду `ssh` в PowerShell по инструкции выше.

#### 1. Установите расширение

В VS Code откройте **Extensions** сочетанием `Ctrl+Shift+X` (`Cmd+Shift+X` на macOS), найдите **Remote - SSH** от **Microsoft** и установите его.

#### 2. Используйте проверенную команду подключения

Для этого способа завершите вход командой `ssh` на шаге 9. Сохраните ту команду, с которой удалось подключиться, включая порт: например, `ssh alex@192.168.1.50` или `ssh -p 2222 alex@192.168.1.50`. После проверки выйдите командой `exit`. Проверка только через PuTTY не подтверждает готовность OpenSSH-клиента для VS Code.

#### 3. Добавьте сервер в VS Code

1. Откройте палитру команд сочетанием `Ctrl+Shift+P` (`Cmd+Shift+P` на macOS);
2. Выберите **Remote-SSH: Add New SSH Host…**;
3. Введите ту же полную команду, с которой проверили вход: `ssh ЛОГИН@ХОСТ` или `ssh -p 2222 ЛОГИН@ХОСТ` с вашим портом;
4. Выберите SSH-конфиг своей учётной записи, обычно `C:\Users\<ваше_имя>\.ssh\config` на Windows или `~/.ssh/config` на macOS и Linux. Расширение сохранит адрес, логин и порт; пароль в эту команду и файл не вписывайте.

#### 4. Подключитесь и откройте папку

1. Снова откройте палитру команд;
2. Выберите **Remote-SSH: Connect to Host…**, затем добавленный сервер;
3. Если VS Code запросит тип системы сервера, выберите **Linux**. При запросе доверия сверяйте отпечаток, как при входе через терминал; затем введите пароль;
4. Дождитесь подключения: в левом нижнем углу окна должен появиться индикатор **SSH: …** с именем сервера;
5. Выберите **File → Open Folder…** и откройте нужную папку на сервере, к которой у вас есть доступ.

Изменения файлов в таком окне сохраняются непосредственно на удалённом сервере. Открытый в этом окне терминал тоже выполняет команды на сервере. Чтобы отключиться, выберите **File → Close Remote Connection**. Команда `exit` закрывает отдельный терминальный сеанс, но не отключает окно VS Code.

Если вход командой `ssh` на шаге 9 работает, а VS Code не подключается, откройте **View → Output**, выберите канал **Remote - SSH** и передайте полный текст ошибки преподавателю.

### 11. Установите и проверьте один движок контейнеров

Эти действия снова выполняются **на вашем компьютере**. Выйдите из SSH командой `exit` или отключите удалённое окно VS Code через **File → Close Remote Connection**. Откройте обычный локальный терминал. Если проверку делаете через редактор, откройте локальную папку комплекта курса и создайте новый терминал в ней.

Выберите один вариант: Docker или Podman. Если один из них уже установлен и работает, второй устанавливать не требуется.

#### Вариант 1. Docker

1. Откройте [официальную страницу установки Docker](https://docs.docker.com/get-started/get-docker/) и выберите свою систему;
2. На Windows или macOS установите Docker Desktop и запустите его из меню приложений. На Windows выполните требования установщика к WSL 2 и перезагрузите компьютер, если это запрошено. На Linux выберите подходящую установку из документации и запустите установленный движок;
3. Дождитесь готовности Docker Desktop или службы Docker. Затем откройте новый локальный терминал и выполните:

   ```bash
   docker version
   ```

   В выводе должны быть сведения и о клиенте **Client**, и о серверной части **Server**. Сообщение о невозможности подключиться к движку означает, что этот шаг ещё не завершён;
4. Загрузите учебный образ:

   ```bash
   docker pull docker.io/library/python:3.14.7-slim
   ```

   Дождитесь завершения загрузки без ошибки;
5. Выполните короткую проверку запуска:

   ```bash
   docker run --rm docker.io/library/python:3.14.7-slim python --version
   ```

   Ожидаемый результат — `Python 3.14.7`. Параметр `--rm` удаляет пробный контейнер после завершения; загруженный образ остаётся для следующих запусков.

#### Вариант 2. Podman

1. Откройте [официальную инструкцию установки Podman](https://podman.io/docs/installation) и установите его для своей системы. На Windows или macOS выберите официальный установщик; на Linux используйте пакет своего дистрибутива;
2. На Windows или macOS подготовьте и запустите виртуальную машину Podman. При первой настройке выполните:

   ```bash
   podman machine init
   podman machine start
   ```

   Если машина уже создавалась, не повторяйте `init`: посмотрите `podman machine list` и запустите `podman machine start`, только если она остановлена. На Linux этот шаг с виртуальной машиной обычно не нужен;
3. В новом локальном терминале выполните:

   ```bash
   podman version
   podman info
   ```

   Обе команды должны завершиться без ошибки соединения с движком;
4. Загрузите учебный образ:

   ```bash
   podman pull docker.io/library/python:3.14.7-slim
   ```

   Дождитесь завершения загрузки без ошибки;
5. Проверьте запуск:

   ```bash
   podman run --rm docker.io/library/python:3.14.7-slim python --version
   ```

   Ожидаемый результат — `Python 3.14.7`.

Если установка требует прав или системных возможностей, которых у вас нет, сохраните сообщение и обратитесь к преподавателю для восстановления или согласованного резерва. При ошибке запуска не переходите к проверке курса: сначала должен заработать выбранный движок.

#### Запустите контейнерный профиль проверки курса

Откройте **корень локального комплекта курса**, как на шаге 7, и выполните команду своей системы.

На Windows:

```powershell
py -3.14 scripts/preflight.py --profile containers
```

На macOS или Linux с командой `python3.14`:

```bash
python3.14 scripts/preflight.py --profile containers
```

На Ubuntu после установки Python из справочного раздела:

```bash
/opt/python-3.14.7/bin/python3.14 scripts/preflight.py --profile containers
```

Профиль повторит базовую проверку, найдёт работающий Docker или Podman, убедится в наличии уже загруженного образа и запустит в нём Python. Сам образ сценарий не скачивает.

Последняя строка должна начинаться с `ПРЕДВАРИТЕЛЬНАЯ ПРОВЕРКА ПРОЙДЕНА` и заканчиваться `контейнерный запуск через docker` или `контейнерный запуск через podman`. Если оба движка уже установлены и работают, сценарий сначала выбирает Podman; устанавливать второй ради проверки не нужно.

Этап Б завершён, когда:

- при входе по SSH проверен отпечаток сервера, а `whoami` показывает ваш логин;
- вы умеете завершать удалённый сеанс и возвращаться к локальному терминалу;
- контейнерный профиль `preflight.py` проходит на вашем компьютере;
- если выбрали VS Code для удалённой работы, нужная папка открывается в окне с индикатором **SSH: …**.

## Как обратиться за помощью

Если шаг не проходит, остановитесь на первой ошибке и передайте в постоянный канал `setup`:

- номер шага и название выбранного варианта;
- название операционной системы;
- место выполнения команды: свой компьютер или удалённый сервер;
- введённую команду и полный текст результата.

Пароль, закрытые ключи, токены и содержимое `.env` не присылайте. Преподаватель подтверждает получение ответом `Принято преподавателем: <номер вопроса>`. До видимого подтверждения не считайте обращение обработанным. Неизвестная блокировка получает техническую консультацию; переустанавливать все инструменты подряд не требуется.

## Справка: установка Python 3.14.7 на Ubuntu 24.04 LTS

Последовательность ниже воспроизведена 9 сентября 2026 года в чистом Ubuntu 24.04 LTS на ARM64: контрольная сумма архива совпала, установленный интерпретатор и созданная им `.venv` показали `Python 3.14.7`, а `pip` запустился. Команды используют официальный архив Python и рекомендации по зависимостям сборки CPython. Для выполнения нужны `sudo`, доступ в интернет и свободное место для исходников и сборки.

Установите инструменты и библиотеки сборки:

```bash
sudo apt update
sudo apt install --no-install-recommends build-essential pkg-config ca-certificates curl xz-utils \
  libbz2-dev libffi-dev libgdbm-dev liblzma-dev libncurses-dev libreadline-dev \
  libsqlite3-dev libssl-dev tk-dev uuid-dev zlib1g-dev
```

Скачайте официальный архив, проверьте его контрольную сумму и распакуйте:

```bash
cd /tmp
curl -fsSLO https://www.python.org/ftp/python/3.14.7/Python-3.14.7.tar.xz
printf '%s  %s\n' \
  '3b48dac8fb59f62eaa67ac83c1eb12bda1b7a08406dd286e252c11a66be27f81' \
  'Python-3.14.7.tar.xz' | sha256sum -c -
tar -xf Python-3.14.7.tar.xz
cd Python-3.14.7
```

Строка проверки должна быть `Python-3.14.7.tar.xz: OK`. После неё соберите интерпретатор в отдельный каталог, не заменяя системный Python:

```bash
./configure --prefix=/opt/python-3.14.7 --with-ensurepip=install
make -j2
sudo make install
/opt/python-3.14.7/bin/python3.14 --version
```

Ожидается `Python 3.14.7`. В шагах 6, 7 и 11 используйте отдельные блоки с полным путём `/opt/python-3.14.7/bin/python3.14`. После установки вернитесь к шагу 3 основного маршрута.

Если у вас нет `sudo`, используется другой выпуск Linux либо любая команда выше завершилась не ожидаемой строкой, остановитесь и запросите управляемый резерв в `setup`. До срока подготовки преподаватель назначает раннюю техническую консультацию или предоставляет резервный университетский компьютер с Ubuntu 24.04 LTS, на котором проектная предварительная проверка уже проходит. В обращении приложите первую ошибку и вывод:

```bash
cat /etc/os-release
python3 --version
```
