# Домашняя работа 3 — HTTP API, бой и Compose

## Результат

Продолжите `console-quest`: разделите его на клиент и сервер без Django, реализуйте четыре операции JSON API, включая чистый расчёт одного удара, завершите клиентский цикл боя и запустите два сервиса через Compose.

На работу отводится до 180 минут активного времени. Сервер временно читает сценарий из YAML; перенос в SQLite выполняется только в HW04.

## Зафиксируйте четыре операции

Реализуйте одинаковый внешний договор в OpenAPI, сервере, клиенте и тестах:

| Метод и путь | Успех | Назначение |
|---|---:|---|
| `POST /api/v1/characters/initialize` | `200` | Вернуть начальное состояние персонажа и `current_scene_id`. |
| `GET /api/v1/scenes/{scene_id}` | `200` | Вернуть существующую сцену либо `404`. |
| `POST /api/v1/dice/rolls` | `200` | Вернуть целое `value` от 1 до 6. |
| `POST /api/v1/combat/attacks/resolve` | `200` | Рассчитать один удар по переданным состояниям и броскам. |

Известный путь с неверным методом возвращает `405`, повреждённый или недопустимый JSON — `400`, неизвестный путь или сцена — `404`. Ошибка имеет форму `{"error": {"code": "...", "message": "..."}}`.

## Создайте серверный сценарий

В `server/data/scenario.yaml` самостоятельно опишите минимум пять достижимых ациклических сцен, два финала и один бой. Каждая ветвь завершается; ссылки ведут только к существующим сценам.

Сервер читает этот файл при запуске и не изменяет его. Партия остаётся у клиента.

## Реализуйте чистый расчёт удара

В `server/combat.py` самостоятельно реализуйте функцию, которая получает:

- состояние `player` с `name`, `hp`, `str`, `def`;
- состояние `opponent` с теми же полями;
- `player_roll` и `opponent_roll` как целые числа от 1 до 6.

Функция проверяет вход, выбирает атакующего по броску, затем по `str`, `def` и при полном равенстве в пользу игрока. Урон равен `max(1, attacking.str - defending.def)`. Ответ содержит `attacker`, `damage`, новые состояния `player` и `opponent` и `outcome`; аргументы не изменяются. Функция не читает HTTP, YAML, переменные среды и состояние партии.

## Реализуйте серверную HTTP-границу

`server/http_server.py` разбирает метод, путь и JSON, вызывает предметные функции и собирает статус с JSON-ответом. `server/__main__.py` читает `QUEST_API_BIND` и `QUEST_API_PORT`, запускает сервер и пишет безопасный прикладной лог.

Лог содержит идентификатор запроса, метод, путь, статус и время; полные тела и будущие токены не выводятся. Каждый запрос завершается одной строкой ответа и одной связанной записью лога.

## Реализуйте клиентский адаптер и бой

В `client/api.py` сосредоточьте HTTP и `QUEST_API_URL`. Публичные методы соответствуют четырём операциям. В `client/battle.py` клиент:

1. Запрашивает два броска;
2. отправляет состояния участников и броски в операцию удара;
3. применяет возвращённое состояние локально;
4. меняет роли;
5. повторяет раунды до одного победителя;
6. выбирает `on_win_scene_id` или `on_loss_scene_id`.

Зафиксируйте верхнюю границу числа раундов тестом, чтобы бой гарантированно завершался.

## Добавьте HTTP-тесты

Тесты подтверждают:

- четыре успешные операции;
- бросок в диапазоне 1–6;
- неизменность входного защитника после удара;
- `400`, `404` и `405` со стабильным `error.code`;
- фактический вызов публичных функций адаптера клиентом;
- завершение боя одним победителем.

Сетевой тест запускает сервер на свободном loopback-порту и всегда завершает процесс в `finally`.

## Создайте Compose полным блоком

```yaml
services:
  server:
    build:
      context: .
      dockerfile: server/Dockerfile
    environment:
      QUEST_API_BIND: 0.0.0.0
      QUEST_API_PORT: 8000
      QUEST_DB_PATH: /data/game.sqlite3
    ports:
      - "${QUEST_API_BIND:-127.0.0.1}:${QUEST_API_PORT:-8000}:8000"
    volumes:
      - server-data:/data
    healthcheck:
      test:
        - CMD
        - python
        - -c
        - "import urllib.request; urllib.request.urlopen('http://127.0.0.1:8000/health/', timeout=2)"
      interval: 2s
      timeout: 2s
      retries: 10
  client:
    build:
      context: .
      dockerfile: client/Dockerfile
    environment:
      QUEST_API_URL: http://server:8000
      QUEST_SAVE_PATH: /saves/game.yaml
    depends_on:
      server:
        condition: service_healthy
    volumes:
      - ./saves:/saves
    stdin_open: true
    tty: true
volumes:
  server-data:
```

Объясните в README, почему контейнер клиента использует `server`, а опубликованный порт хоста — `127.0.0.1:8000`.
