# Домашняя работа 6 — модели, миграции и импорт Django

## Результат

Продолжите `django-quest`: создайте связанные модели сценария, сцен, вариантов и боевого действия, миграцию, идемпотентную команду импорта открытого YAML и наблюдаемое представление данных в административной панели.

На работу отводится до 180 минут активного времени. База второго продукта воспроизводится самостоятельно и не копируется из `console-quest`.

## Исходное состояние

Начинайте от чистого тега `hw05-ready`:

```bash
git switch main
git status --short
git tag --list hw05-ready
python manage.py check
python manage.py test -v 2
```

## Перенесите только открытые данные

Создайте каталог `data` и скопируйте собственный `server/data/scenario.yaml` из принятого `console-quest` в `data/scenario.yaml` отдельной наблюдаемой операцией. Не копируйте SQLite-файл, серверный код, окружение или Git-историю первого продукта.

Если первый продукт недоступен, создайте YAML заново по тому же открытому формату. Источник должен содержать минимум восемь достижимых сцен, три финала и один бой.

## Создайте точное дерево этапа

Создайте:

```text
data/scenario.yaml
game/management/__init__.py
game/management/commands/__init__.py
game/management/commands/import_scenario.py
game/scenario_import.py
game/tests/test_models.py
game/tests/test_import_scenario.py
```

Измените существующие `game/models.py` и `game/admin.py`. Файл `game/migrations/0001_initial.py` должен создать генератор Django, а не ручное копирование.

## Спроектируйте четыре модели

Самостоятельно реализуйте:

- `Scenario` с устойчивым внешним идентификатором, названием, стартовой сценой и исходными характеристиками;
- `Scene` со строковым `id` как единственным внешним идентификатором и первичным ключом, видом и описанием, принадлежащую сценарию;
- `Choice` с позицией, текстом, исходной и целевой сценой;
- `BattleAction` с ровно одной записью для боевой сцены, противником и переходами победы и поражения.

Задайте осмысленные `related_name`, `on_delete`, обязательность полей и ограничения. `Scene.id` уникален во всей таблице как первичный ключ; второе поле внешней идентичности не создаётся. Позиция варианта уникальна внутри исходной сцены; боевое действие уникально для сцены. Во всех последующих запросах сцена ищется через `pk=scene_id`.

## Начните с красного теста ограничения

В `game/tests/test_models.py` сначала создайте тест, который пытается записать второй вариант с той же позицией в одной сцене. До ограничения тест должен падать, после его добавления — получить `IntegrityError` внутри `transaction.atomic()`.

```bash
python manage.py test game.tests.test_models -v 2
```

Добавьте тесты отношений, `PROTECT` для используемой целевой сцены и допустимого создания боевого действия.

## Создайте и прочитайте миграцию

Сначала спрогнозируйте таблицы, внешние ключи и ограничения, затем выполните:

```bash
python manage.py makemigrations game --name initial
python manage.py migrate --plan
python manage.py sqlmigrate game 0001
python manage.py migrate
python manage.py showmigrations game
```

Наблюдаемый результат:

- появился `game/migrations/0001_initial.py`;
- `sqlmigrate` показывает ожидаемые таблицы и ограничения;
- `showmigrations` отмечает `0001_initial` как `[X]`;
- `python manage.py makemigrations --check --dry-run` возвращает код `0`.

Не редактируйте миграцию вручную ради совпадения с прогнозом: сначала исправляйте модель и создавайте файл заново только до принятого коммита.

## Реализуйте команду импорта

`python manage.py import_scenario data/scenario.yaml` должна сначала через `game/scenario_import.py` полностью проверить версию, уникальность идентификаторов, виды сцен, все ссылки, достижимость и отсутствие циклов, а затем:

1. Полностью прочитать и проверить YAML до изменения базы;
2. выполнить запись в транзакции;
3. создать или обновить сценарий и связанные строки;
4. удалить только устаревшие воспроизводимые строки этого сценария;
5. при повторе оставить тот же набор данных;
6. при ошибке откатить всю операцию.

Команда не создаёт пользователя и владельца; эта связь появится в HW08.

## Проверьте чистую базу

Остановите сервер. Удалите только локальный `db.sqlite3`, затем выполните:

```bash
python manage.py migrate
python manage.py import_scenario --source data/scenario.yaml
python manage.py import_scenario --source data/scenario.yaml
python manage.py test game.tests.test_import_scenario -v 2
```

Оба импорта завершаются кодом `0`, количества строк не растут, все связи восстанавливаются из миграции и YAML.

## Выполните ORM-наблюдения

Через `python manage.py shell`:

- создайте отдельный тестовый объект через `create`;
- найдите множество через `filter`;
- получите одну сцену через `get`;
- пройдите от сценария к сценам по обратной связи;
- удалите тестовый объект, не затрагивая импортированный сценарий.

Зафиксируйте SQL или объясните, какой `JOIN` соответствует одному наблюдению.

## Настройте административную панель

Зарегистрируйте четыре модели. Добавьте полезные `list_display` и `search_fields`, не скрывая ключевые связи.

```bash
python manage.py createsuperuser
python manage.py runserver 127.0.0.1:8000
```

В `/admin/` наблюдаются сценарий, сцены, варианты и боевое действие. Пароль суперпользователя не попадает в Git, YAML или журнал.
