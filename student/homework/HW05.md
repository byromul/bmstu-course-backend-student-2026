# Домашняя работа 5 — новый `django-quest` из пустого каталога

## Результат

Начните второй независимый продукт: из нового пустого каталога создайте Git-репозиторий, окружение, проект Django `quest`, приложение `game`, health-маршрут и короткий SSR-маршрут. `console-quest` не является входным деревом этой работы.

На работу отводится до 120 минут активного времени. Проверяется происхождение структуры от генераторов и первый путь `запрос → URLconf → представление → ответ`.

## Исходное состояние

До начала доступны Python 3.14.7, Git и комплект курса. Выберите пустой родительский каталог, в котором нет `django-quest`, и снова выполните общий preflight из комплекта курса.

Каталог `console-quest`, его виртуальное окружение, база и запущенные процессы для HW05 не нужны.

## Создайте новый продукт

```bash
mkdir django-quest
cd django-quest
git init -b main
python3.14 -m venv .venv
source .venv/bin/activate
```

В Windows PowerShell последняя команда заменяется на `.venv\Scripts\Activate.ps1`. Проверьте Python и корень Git:

```bash
python --version
git rev-parse --show-toplevel
git branch --show-current
```

Ожидаются Python 3.14.7, путь с окончанием `django-quest` и ветка `main`.

## Создайте механическую конфигурацию

`.gitignore`:

```text
.venv/
__pycache__/
*.pyc
.ruff_cache/
db.sqlite3
*.sqlite3

```

`.env.example`:

```text
DJANGO_SECRET_KEY=задайте-локальное-значение-вне-git
DJANGO_DB_PATH=db.sqlite3
```

Создайте локальный файл из опубликованного образца и замените только значение ключа на собственную непустую строку:

```bash
cp .env.example .env
```

В Windows PowerShell используйте `Copy-Item .env.example .env`. Не добавляйте `.env` в Git.

`requirements.lock`:

```text

```

`pyproject.toml`:

```toml
[tool.ruff]

line-length = 100
exclude = ["**/migrations/*.py"]

[tool.ruff.lint]
```

Установите зависимости:

```bash
python -m pip install -r requirements.lock
python -m django --version
```

Вторая команда должна напечатать `5.2.17`.

## Запустите генераторы Django

Из корня пустого `django-quest` выполните:

```bash
python -m django startproject quest .
python manage.py startapp game
```

Первая команда создаёт `manage.py` и пакет проекта `quest`, вторая — приложение `game`. Удалите созданный генератором `game/tests.py`, затем создайте каталог `game/tests` и пустой `game/tests/__init__.py`.

Не копируйте Django-файлы из эталона или первого продукта.

## Подключите приложение

В `quest/settings.py` добавьте `game` в `INSTALLED_APPS`, до обращения к `SECRET_KEY` прочитайте существующий `.env`, перенесите только `DJANGO_SECRET_KEY` и `DJANGO_DB_PATH` в `os.environ` через `setdefault` и сохраните SQLite по пути `DJANGO_DB_PATH` с локальным значением `db.sqlite3` по умолчанию. Команда `python manage.py check` должна работать в новом терминале без предварительного `export`.

Настоящий `DJANGO_SECRET_KEY` храните в `.env`, который исключён из Git. Для тестов допустим отдельный стабильный тестовый ключ, но не производственный секрет.

Проверьте конфигурацию:

```bash
python manage.py check
```

Ожидаемая последняя строка — `System check identified no issues`.

## Создайте первый URLconf и представления

Создайте `game/urls.py`. В `game/views.py` самостоятельно реализуйте:

- `health`, возвращающий JSON `{"status": "ok"}`;
- `welcome`, передающий безопасный `message` и параметр `name` в шаблон.

Подключите `game.urls` из `quest/urls.py`. Health доступен по `/health/`, а именованный маршрут `game:welcome` — по `/welcome/`.

## Добавьте открытые тесты

В `game/tests/test_views.py` создайте открытые тесты полным блоком:

```python
"""Открытые тесты первого этапа Django."""

from django.test import TestCase
from django.urls import reverse


class ViewTests(TestCase):
    def test_health_returns_json(self) -> None:
        response = self.client.get("/health/")
        self.assertEqual(response.status_code, 200)
        self.assertEqual(response.json(), {"status": "ok"})

    def test_named_welcome_route_escapes_context(self) -> None:
        response = self.client.get(reverse("game:welcome"), {"name": "<script>"})
        self.assertEqual(response.status_code, 200)
        self.assertContains(response, "&lt;script&gt;")
        self.assertNotContains(response, "<script>")
```

До реализации представлений запустите один тест и получите ожидаемый красный ответ маршрутизации, затем реализуйте минимальное поведение:

```bash
python manage.py test game.tests.test_views -v 2
```

Зелёный результат — два теста проходят.
