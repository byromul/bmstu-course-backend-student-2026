## Шаг 6. Задайте три сцены

Создайте `client/domain.py` со следующим первым блоком:

```python
"""Предметное состояние и переходы первого этапа."""

from __future__ import annotations

from dataclasses import dataclass, replace

SCENES = {
    "START": {
        "id": "START",
        "kind": "choice",
        "description": "Перед вами две двери.",
        "choices": (
            {"text": "Открыть светлую дверь", "next_scene_id": "WIN"},
            {"text": "Открыть тёмную дверь", "next_scene_id": "LOSS"},
        ),
    },
    "WIN": {
        "id": "WIN",
        "kind": "ending",
        "description": "Вы нашли выход.",
        "ending": "positive",
    },
    "LOSS": {
        "id": "LOSS",
        "kind": "ending",
        "description": "Путь завершился неудачей.",
        "ending": "negative",
    },
}
```

`SCENES` — словарь сцен: `START` содержит два варианта, `WIN` и `LOSS` содержат финалы. Поле `next_scene_id` связывает вариант с другой сценой, а `kind` позволяет отличить выбор от финала. Порядок в `choices` важен: первый вариант ведёт к `WIN`, второй к `LOSS`. Импорты `dataclass` и `replace` понадобятся в следующих шагах. Здесь нет `input()` и `print()`: предметная модель не зависит от терминала.

Проверьте импорт и второй переход:


`python -c` выполняет короткий код без создания нового файла. Индекс `[1]` означает второй элемент, потому что индексация начинается с нуля. Ожидаемый вывод — `LOSS`. Если возник `SyntaxError`, сравните скобки, запятые и кавычки с блоком выше.

## Шаг 7. Добавьте состояние и получение сцены

**Допишите в конец `client/domain.py`**, не удаляя `SCENES`:

```python
@dataclass(frozen=True)
class GameState:
    current_scene_id: str
    name: str
    hp: int
    strength: int
    defense: int

    @classmethod
    def new(cls, name: str) -> GameState:
        return cls("START", name, 10, 3, 2)


def get_scene(scene_id: str) -> dict[str, object]:
    try:
        return SCENES[scene_id]
    except KeyError as error:
        raise ValueError(f"Неизвестная сцена: {scene_id}") from error
```

`GameState` хранит текущую сцену, имя и характеристики героя. `@dataclass(frozen=True)` запрещает менять поля созданного объекта. `new` создаёт исходное состояние: `START`, `hp = 10`, `strength = 3` и `defense = 2`. `get_scene` возвращает известную сцену, а неизвестный идентификатор переводит из `KeyError` словаря в `ValueError` с понятным сообщением.


Команда создаёт объект только в памяти. В выводе должны быть `current_scene_id='START'`, `hp=10`, `strength=3`, `defense=2` и строка `choice`.

## Шаг 8. Добавьте переход по номеру

**Допишите в конец `client/domain.py`**:

```python
def choose(state: GameState, number: object) -> GameState:
    if not isinstance(number, int):
        raise ValueError("Номер выбора должен быть целым числом")
    scene = get_scene(state.current_scene_id)
    choices = scene.get("choices", ())
    if not 1 <= number <= len(choices):
        raise ValueError(f"Номер выбора должен быть от 1 до {len(choices)}")
    target = choices[number - 1]["next_scene_id"]
    return replace(state, current_scene_id=target)
```

`choose` проверяет, что номер целый и попадает в диапазон вариантов текущей сцены. Номер `1` превращается в индекс `0`, номер `2` — в индекс `1`. `replace` создаёт новый `GameState`, меняя только `current_scene_id`. При ошибке исходное состояние остаётся прежним.

Ожидаемый вывод — `WIN LOSS START`. Последнее значение показывает, что два выбора не изменили `start`.

## Шаг 9. Запустите промежуточную версию клиента

Создайте `client/__main__.py` с первым работающим вариантом:

```python
"""Первый запуск консольного клиента."""

from client.domain import GameState, get_scene


def main() -> None:
    name = input("Имя героя: ").strip() or "Игрок"
    state = GameState.new(name)
    scene = get_scene(state.current_scene_id)
    print(scene["description"])
    for index, item in enumerate(scene["choices"], start=1):
        print(f"{index}. {item['text']}")


if __name__ == "__main__":
    main()
```

Импорт связывает точку входа с `domain.py`. `input` получает имя, `strip` убирает пробелы по краям, а `or "Игрок"` даёт имя по умолчанию. `enumerate(..., start=1)` нумерует варианты так, как их видит игрок. Последнее условие запускает `main` только при выполнении модуля как программы.

Запустите:

```bash
python -m client
```

Введите имя и нажмите Enter. Программа должна показать описание `START` и два нумерованных варианта, затем завершиться. Чтение выбора появится на следующем шаге. Если выводится `No module named client`, вернитесь в корень `console-quest` и проверьте `client/__init__.py`.

## Шаг 10. Добавьте цикл игры

**Полностью замените `client/__main__.py`** проверенным конечным вариантом:

```python
"""Консольная точка входа первого этапа."""

from client.domain import GameState, choose, get_scene


def main() -> None:
    name = input("Имя героя: ").strip() or "Игрок"
    state = GameState.new(name)
    while True:
        scene = get_scene(state.current_scene_id)
        print(scene["description"])
        if scene["kind"] == "ending":
            print(f"Финал: {scene['ending']}")
            return
        for index, item in enumerate(scene["choices"], start=1):
            print(f"{index}. {item['text']}")
        try:
            state = choose(state, int(input("Ваш выбор: ")))
        except (ValueError, TypeError) as error:
            print(f"Ошибка ввода: {error}")


if __name__ == "__main__":
    main()
```

`while True` показывает текущую сцену повторно. Если `kind` равен `ending`, программа печатает финал и `return` завершает её с кодом `0`. Иначе она печатает варианты, читает строку, превращает её в `int` и вызывает `choose`. Присваивание `state = ...` выполняется только после успешного возврата: при `ValueError` или `TypeError` прежнее состояние остаётся и цикл повторяет ту же сцену. Не перехватывайте `Exception` вокруг всей программы: неожиданный дефект должен сохранить трассировку.

Запустите `python -m client` три раза и введите:

- В первом запуске имя и `1`: ожидается `Финал: positive`;
- Во втором имя и `2`: ожидается `Финал: negative`;
- В третьем имя, `два` и `1`: ожидаются `Ошибка ввода: ...`, повтор описания `START` и `Финал: positive`.

Те же маршруты можно проверить копируемыми командами без ручного набора. Каждая команда запускает новый процесс с тем же интерпретатором, передаёт строки через `input` и печатает вывод вместе с кодом завершения:

```bash
python -c "import subprocess, sys; r = subprocess.run([sys.executable, '-m', 'client'], input='Лина\n1\n', text=True, capture_output=True); print(r.stdout); print('Код:', r.returncode)"
```

Эта команда должна показать оба варианта, `Финал: positive` и `Код: 0`.

```bash
python -c "import subprocess, sys; r = subprocess.run([sys.executable, '-m', 'client'], input='Лина\n2\n', text=True, capture_output=True); print(r.stdout); print('Код:', r.returncode)"
```

Эта команда должна показать `Финал: negative` и `Код: 0`.

```bash
python -c "import subprocess, sys; r = subprocess.run([sys.executable, '-m', 'client'], input='Лина\nдва\n1\n', text=True, capture_output=True); print(r.stdout); print('Код:', r.returncode)"
```

Эта команда должна показать `Ошибка ввода:`, два появления `Перед вами две двери.`, `Финал: positive` и `Код: 0`. Для номера `3` восстановление такое же. Если процесс не завершается, проверьте отступ `return` внутри ветки финала и строку присваивания `state` после `choose`.

`git remote add` связывает локальное имя `origin` с удалённым адресом; эта команда ещё ничего не отправляет. `git remote -v` показывает адрес для чтения и отправки. Оба должны вести в **ваш** пустой `console-quest`. Если `origin` уже существует после повторной попытки, не добавляйте его снова: проверьте `git remote -v` и продолжите с верным адресом. Если адрес ошибочен, исправьте его командой `git remote set-url origin АДРЕС_ВАШЕГО_РЕПОЗИТОРИЯ`.

При отправке по HTTPS GitHub может открыть вход через менеджер учётных данных. Обычный пароль учётной записи для `git push` не используется: при запросе пароля нужен токен доступа или настроенный менеджер учётных данных. Не вставляйте токен в адрес `origin`, код, команды задания или Git-коммит. Если вход не проходит, выполните [инструкцию GitHub по аутентификации](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/about-authentication-to-github), затем повторите отправку на следующем шаге.

## Шаг 13. Сохраните и отправьте проверенное состояние

Проверьте состав изменения и создайте один локальный коммит. `git status --short` показывает новые файлы, `git diff` показывает изменения уже отслеживаемых файлов, а `git add` помещает перечисленные файлы в индекс Git. `git diff --staged` даёт проверить точное содержимое коммита перед фиксацией:

```bash
git status --short
git diff
git add .gitignore README.md client/__init__.py client/domain.py client/__main__.py
git diff --staged
git commit -m "feat(client): добавить локальный цикл квеста"
git tag hw01-ready
git show --no-patch --oneline hw01-ready
git log -1 --oneline
git status --short
```

`git commit` фиксирует подготовленное состояние, а `git tag` даёт ему имя `hw01-ready`. `git show` и `git log` должны показать один и тот же коммит; `git status --short` в конце не печатает строк. Не используйте `git add .`: рядом может оказаться временный файл. Если Git просит автора, задайте его локально командами `git config user.name "Ваше имя"` и `git config user.email "ваш@адрес"`, затем повторите коммит и тег.

Отправьте только проверенные ветку и тег в созданный пустой репозиторий:

```bash
git push -u origin main
git push origin hw01-ready
```

Первая команда отправляет коммит ветки `main`; флаг `-u` запоминает связь локальной ветки с `origin/main`. Вторая команда отдельно отправляет тег: обычный `git push` тег автоматически не публикует. Если сервер отклонил отправку из-за чужих коммитов, не используйте `--force`: проверьте адрес `origin` и что при создании репозитория вы не добавили начальные файлы. При ошибке входа вернитесь к инструкции предыдущего шага.

Убедитесь, что GitHub получил обе ссылки:

```bash
git ls-remote --heads origin main
git ls-remote --tags origin hw01-ready
git status --short
```

Первые две команды должны вывести по строке с хешем и ссылкой `refs/heads/main` или `refs/tags/hw01-ready`. Хеши должны совпадать: ветка и тег указывают на один проверенный коммит. Последняя команда остаётся пустой. Обновите страницу репозитория GitHub: файлы первого этапа видны в `main`, а `hw01-ready` — в списке тегов.

## Критерии готовности

Статус «готово» ставится, если одновременно:

- Продукт начат в пустом каталоге и содержит только объявленное дерево первого этапа;
- `.venv` создана отдельно и исключена из Git;
- Предметная модель допускает оба выбора и отклоняет недопустимый номер без изменения исходного состояния;
- Оба финала достижимы, а неверный ввод не меняет текущую сцену;
- `domain.py` не выполняет терминальный ввод и вывод;
- Внешняя проверка завершилась кодом `0` и записала отчёт вне продукта;
- Локальный коммит содержит объявленные файлы, рабочее дерево чистое, а ветка `main` и тег `hw01-ready` отправлены в собственный репозиторий GitHub и указывают на этот коммит.

Если критерий не выполнен, работа получает формирующий статус «нужно продолжение» и одно конкретное следующее действие.
