# Домашняя работа 1 — `console-quest` из пустого каталога

## Результат

Создайте в новом пустом каталоге первую запускаемую версию `console-quest`: локальный консольный квест на Python 3.14.7 с тремя сценами, двумя достижимыми финалами и восстановлением после неверного ввода. Сервер, база данных, сохранение, автоматические тесты, внешние пакеты и контейнеры пока не участвуют. Тестирование предметной модели начинается после лекции 2.

На работу отводится до 150 минут активного времени, включая 15 минут обязательного чтения, назначенного в L01. Литературное качество и оригинальность сюжета не оцениваются; проверяются происхождение файлов, публичные границы, переходы, наблюдаемое поведение и воспроизводимый Git-коммит.

## Исходное состояние

До начала существует:

- установленный Python 3.14.7;
- установленный и настроенный Git;
- распакованный комплект курса с `scripts/preflight.py` и внешней проверкой `student/checks/check.py`;
- пустой родительский каталог, в котором ещё нет `console-quest`.

Внутри продукта нет исходного кода, конфигурации, истории Git и скрытых файлов курса. Не копируйте старый каркас, эталон преподавателя или задачи лекции.

Сначала из корня комплекта курса выполните:

```bash
python scripts/preflight.py
```

Успех — последняя строка `ПРЕДВАРИТЕЛЬНАЯ ПРОВЕРКА ПРОЙДЕНА` и код завершения `0`. Если точный интерпретатор называется `py -3.14` или `python3.14`, используйте это имя и в следующих командах до активации окружения.

## Создайте продукт и локальную историю

Из выбранного родительского каталога создайте продукт и сделайте его текущим каталогом:


Наблюдаемый результат:

- `git branch --show-current` печатает `main`;
- `git status --short` пока не печатает строк.

Создайте виртуальное окружение одной командой для своей системы.

Windows PowerShell:



Первая команда должна показать `Python 3.14.7`, вторая — путь внутри `console-quest/.venv`. HW01 использует только стандартную библиотеку, поэтому установка пакетов здесь не нужна. Первый файл точных зависимостей появится в HW02 вместе с Ruff и YAML.

`README.md` кратко фиксирует Python 3.14.7, команду `python -m client` и наблюдаемый результат: два финала достижимы, неверный ввод не меняет сцену.

## Объявите публичную предметную границу

В `client/domain.py` самостоятельно объявите и реализуйте следующие элементы:

- `SCENES` — словарь трёх сцен с идентификаторами `START`, `WIN` и `LOSS`;
- неизменяемый `GameState` с полями `current_scene_id`, `name`, `hp`, `strength` и `defense`;
- `GameState.new(name)`, создающий состояние `START` с `hp = 10`, `strength = 3` и `defense = 2`;
- `get_scene(scene_id)`, возвращающий сцену или возбуждающий `ValueError` для неизвестного идентификатора;
- `choose(state, number)`, проверяющий целый номер, выбирающий вариант по индексу `number - 1` и возвращающий новое состояние с другим `current_scene_id`.

Форма каждой сцены фиксирована:

- `START` содержит `id`, `kind: "choice"`, `description` и два элемента `choices`;
- каждый вариант содержит `text` и `next_scene_id`;
- `WIN` и `LOSS` содержат `id`, `kind: "ending"`, `description` и `ending` со значением `positive` или `negative`.

`domain.py` не вызывает `input()` и `print()`. Недопустимый тип номера даёт `ValueError` с фразой `целым числом`, номер вне диапазона — `ValueError` с фразой `от 1 до 2`. Неизменяемое состояние позволяет вернуть новый объект и не изменить другую партию.

## Проверьте предметное правило вручную

Для `get_scene` проверьте существующие `START`, `WIN` и `LOSS`, затем неизвестный идентификатор. Для `choose` проследите оба допустимых номера, текст вместо числа и номер вне диапазона. При ошибке исходное состояние должно оставаться прежним. Автоматические тесты этих правил вы создадите в HW02 после разбора `unittest` на лекции 2.

Проследите одну ветвь письменно:

1. Терминал передаёт строку `"2"`;
2. Точка входа преобразует её в целое число `2`;
3. Функция `choose` проверяет диапазон и получает индекс `1`;
4. Второй вариант даёт `next_scene_id = "LOSS"`;
5. Новое состояние получает `current_scene_id = "LOSS"`.

## Реализуйте консольную точку входа

В `client/__main__.py` самостоятельно реализуйте `main()` и защитите запуск условием `if __name__ == "__main__"`. Используйте публичные границы `GameState.new`, `get_scene` и `choose`.

Программа выполняет следующий цикл:

1. Читает имя героя и создаёт начальное состояние;
2. Получает текущую сцену и печатает её описание;
3. Для финальной сцены печатает `Финал: <значение>` и завершает процесс кодом `0`;
4. Для начальной сцены печатает оба нумерованных варианта и читает одну строку;
5. Преобразует строку в целое число и передаёт его в `choose`;
6. При `ValueError` или `TypeError` печатает `Ошибка ввода: <причина>` и повторяет ту же сцену.

Не перехватывайте `Exception` вокруг всей программы. Неожиданный дефект должен сохранить трассировку.

Проверьте три маршрута командой `python -m client`:

- выбор `1` достигает финала `positive`;
- выбор `2` достигает финала `negative`;
- сначала текст или номер `3`, затем допустимый номер печатают `Ошибка ввода`, повторяют описание `START` и завершают выбранный финал.

## Запустите внешнюю проверку

Внешнее средство находится в комплекте курса, а не в продукте. Из корня `console-quest` замените `<КАТАЛОГ_КУРСА>` абсолютным путём к распакованному комплекту и выполните:


Проверка читает продукт, создаёт отдельное временное зеркало и не записывает файлы внутрь `console-quest`. Успех — строка `ПРОЙДЕНО: console-quest HW01`, код завершения `0` и поле `status: "passed"` в `../course-reports/HW01.json`.

Если проверка сообщает первое расхождение, исправьте только названный критерий, повторите соответствующий запуск клиента и снова запустите ту же внешнюю команду.

## Сохраните проверенное состояние

Проверьте состав изменения и создайте один локальный коммит:

```bash
git status --short
git diff
git add .gitignore README.md client/__init__.py client/domain.py client/__main__.py
git diff --staged
git commit -m "feat(client): добавить локальный цикл квеста"
git tag hw01-ready
git show --no-patch --oneline hw01-ready
git log -1 --oneline
git status --short
```

Не используйте `git add .`: рядом может оказаться временный файл. Последняя команда не должна печатать строк. Удалённый репозиторий для прохождения HW01 не требуется; если преподаватель отдельно выдал место сдачи, публикация выполняется по его явной инструкции без переписывания истории.

## Критерии готовности

Статус «готово» ставится, если одновременно:

- продукт начат в пустом каталоге и содержит только объявленное дерево первого этапа;
- `.venv` создана отдельно и исключена из Git;
- предметная модель допускает оба выбора и отклоняет недопустимый номер без изменения исходного состояния;
- оба финала достижимы, а неверный ввод не меняет текущую сцену;
- `domain.py` не выполняет терминальный ввод и вывод;
- внешняя проверка завершилась кодом `0` и записала отчёт вне продукта;
- локальный коммит содержит объявленные файлы, рабочее дерево чистое, создан тег `hw01-ready`.

Если критерий не выполнен, работа получает формирующий статус «нужно продолжение» и одно конкретное следующее действие.
