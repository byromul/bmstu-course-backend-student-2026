# EX06 — настройка логирования

Пример использует Python 3.14.7 и только стандартную библиотеку. `logging` уже входит в Python; инструкция `import logging` подключает модуль. Объект `logger`, полученный через `logging.getLogger("quest")`, записывает события с именем `quest`.

## Вывод в терминал

Из каталога `student/lectures/` выполните:

```bash
python examples/L02-EX06/console_demo.py
```

Ожидается:

```text
INFO quest: Ход начат: scene_id=SCN007
INFO quest: Ход завершён: damage=2 hp=4
WARNING quest: Мало здоровья: hp=4
```

`console_demo.py` до первого события настраивает вывод через `logging.basicConfig`, создаёт логгер и передаёт его в `play_turn` из `events.py`. Функция рассчитывает урон и явно записывает результат через `logger.info`. Расчёты не попадают в лог автоматически.

Порог `INFO` скрывает подробное сообщение `DEBUG`. Временно замените в `console_demo.py` `level=logging.INFO` на `level=logging.DEBUG` и повторите запуск. Перед тремя строками появится `DEBUG quest: Исходные данные: hp=6`. Затем восстановите `INFO`.

Без `filename` базовая настройка направляет записи в `stderr`, обычно видимый в терминале. Формат содержит уровень, имя логгера и текст сообщения. В сообщении `%s` заменяется следующим аргументом вызова; в настройке `%(message)s` обозначает уже собранный текст сообщения.

## Запись в файл

Из того же каталога выполните:

```bash
python examples/L02-EX06/file_demo.py
python -c "from pathlib import Path; print(Path('game.log').read_text(encoding='utf-8'), end='')"
```

После первого запуска `game.log` содержит:

```text
DEBUG quest: Исходные данные: hp=6
INFO quest: Ход начат: scene_id=SCN007
INFO quest: Ход завершён: damage=2 hp=4
WARNING quest: Мало здоровья: hp=4
```

Параметры `basicConfig`:

| Параметр | Значение в примере и действие |
|---|---|
| `level` | `logging.DEBUG` пропускает подробности и сообщения более высоких уровней. |
| `format` | `%(levelname)s %(name)s: %(message)s` задаёт вид записи; для времени добавьте `%(asctime)s`. |
| `filename` | `game.log` создаётся в текущем каталоге запуска; записи идут в файл вместо терминала. |
| `encoding` | `utf-8` сохраняет русский текст. |
| `filemode` | `a` дописывает записи; `w` стирает прежнее содержимое при запуске. |

Повторите запуск `file_demo.py`: в конце появятся ещё четыре записи, а прежние останутся. Сам скрипт не выводит сообщения в терминал; в команде выше файл отдельно читает `print`.

Вызывайте `basicConfig` один раз при запуске приложения, до первого события. Если обработчики вывода уже настроены, обычный повторный вызов не заменит их. Поэтому примеры выполняются отдельными процессами Python.

Не записывайте в лог пароль, токен или полный снимок партии. Файл событий помогает диагностике, а восстановление игры использует отдельное сохранение.

## Автономная проверка

```bash
python examples/L02-EX06/check.py
```

Ожидается:

```text
[ТЕРМИНАЛ] INFO и выше; DEBUG скрыт
[ПОРОГ DEBUG] подробное сообщение появилось
[ФАЙЛ] UTF-8; записи двух запусков сохранены
EX06 ПРОЙДЕНА
```

Проверка запускает копии примеров в собственном временном каталоге. Она сверяет фактический вывод с `console.expected.txt` и `file.expected.txt`, проверяет изменение порога и дополнение файла при втором запуске. Каталог удаляется после проверки; `console-quest` не читается и не изменяется.

Источник: [официальное руководство Python по logging](https://docs.python.org/3.14/howto/logging.html) (SRC80), необязательная справка.
