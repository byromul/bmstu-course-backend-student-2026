# EX01 — независимые состояния двух объектов

Задача показывает, почему изменение `first.current_scene_id` не меняет состояние отдельно созданного `second` и почему при `second = first` изменение видно через оба имени. Она связана с K19 и P02 в ACT01 и не использует файлы `console-quest` или `django-quest`.

## Среда и начальное состояние

- Python 3.14.7;
- только стандартная библиотека;
- пустой временный каталог для каждого запуска, в который проверка копирует соответствующий исполняемый файл.

Дерево задачи:

```text
EX01/
├── README.md
├── check.py
├── expected.txt
├── game_state.py
├── shared.expected.txt
└── shared_state.py
```

## Запуск и наблюдаемый результат

Из каталога EX01 выполните:

```text
python game_state.py
```

Ожидаемый стандартный вывод:

```text
END
START
```

Стандартный поток ошибок остаётся пустым, код завершения равен `0`. Времени, случайных значений, портов и внешних путей в примере нет. Долгоживущие процессы не запускаются, а временный каталог автоматической проверки удаляется после завершения.

В `shared_state.py` второе имя связывается с первым экземпляром через `second = first`. Запустите контрпример:

```text
python shared_state.py
```

Ожидаемый вывод:

```text
END
END
```

Присваивание имени не создаёт экземпляр. У обоих имён один объект; обычное изменение его атрибута видно через каждое имя.

Автоматическая проверка обоих вариантов из новых временных каталогов:

```text
python check.py
```

После сборки презентации можно дополнительно сверить копируемый блок со сделанным запуском:

```text
python check.py --html <путь-к-L01.html>
```
