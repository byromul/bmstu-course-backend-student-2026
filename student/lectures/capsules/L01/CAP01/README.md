# CAP01 — независимые состояния двух объектов

Капсула отвечает на один учебный вопрос: почему изменение `first.current_scene_id` не меняет состояние `second`. Она связана с K19 и P02 в ACT01 и не использует файлы `console-quest` или `django-quest`.

## Среда и начальное состояние

- Python 3.14.7;
- только стандартная библиотека;
- пустой временный каталог, в который проверка копирует единственный исполняемый файл `game_state.py`.

Дерево капсулы:

```text
CAP01/
├── README.md
├── check.py
├── expected.txt
└── game_state.py
```

## Запуск и наблюдаемый результат

Из каталога CAP01 выполните:

```text
python game_state.py
```

Ожидаемый стандартный вывод:

```text
END
START
```

Стандартный поток ошибок остаётся пустым, код завершения равен `0`. Времени, случайных значений, портов и внешних путей в примере нет. Долгоживущие процессы не запускаются, а временный каталог автоматической проверки удаляется после завершения.

Автоматическая проверка из нового временного каталога:

```text
python check.py
```

После сборки презентации можно дополнительно сверить копируемый блок со сделанным запуском:

```text
python check.py --html <путь-к-L01.html>
```
