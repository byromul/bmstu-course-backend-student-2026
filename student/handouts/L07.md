# Конспект лекции 7 — DRF, OpenAPI и Swagger UI

Материал дополняет слайды L07. HW07 переносит только утверждённый контракт, а Django REST Framework-реализация создаётся заново.

## Жизненный цикл DRF

Путь запроса:

1. API URLconf выбирает представление;
2. сериализатор проверяет вход;
3. представление использует `validated_data`;
4. ORM читает сценарий либо вызывается чистая функция;
5. `Response` возвращает JSON и явный статус.

DRF работает поверх Django и не заменяет его настройки и маршрутизацию.

## Сериализаторы

Сериализатор описывает поддерживаемые поля, вложенные структуры и ограничения. Ошибка должна указывать поле; недопустимое значение не передаётся предметному правилу.

Для удара проверяются состояния двух участников и броски от 1 до 6.

## Чистый расчёт удара

Функция боя не зависит от DRF и ORM. Она получает проверенные значения, возвращает урон, новое состояние защитника и исход и не изменяет аргументы. Сервер не сохраняет партию.

## Четыре операции и статусы

Успешные операции текущего контракта возвращают `200`. Неверное тело даёт `400`, неизвестная сцена — `404`, известный путь с запрещённым методом — `405`.

Ошибка имеет вложенный `error.code`; тесты не должны зависеть от полного русского сообщения.

## OpenAPI и drf-spectacular

Утверждённый `contracts/openapi.yaml` переносится явно из первого продукта. drf-spectacular строит временную схему из кода:

```bash
python manage.py spectacular --file generated-openapi.yaml --validate
```

Два документа сравниваются по путям, телам, ответам и внешним полям. Сгенерированный файл не заменяет утверждённый контракт.

## Swagger UI и тесты

Swagger UI позволяет вручную отправить запрос. Контрактные тесты проверяют позитивные и негативные случаи через тестовую базу. Ручной запрос не заменяет автоматическую матрицу.

## Автономные капсулы

CAP01 проверяет допустимый и ошибочный запрос сериализатора, CAP02 — чистую функцию удара и неизменность входного защитника.

## Самопроверка

`GET /api/v1/dice/rolls` обращается к существующему пути с запрещённым методом. Ответ: статус `405`, путь к коду `error.code`, значение `method_not_allowed`.
