# Конспект лекции 2 — данные, тесты и безопасное сохранение

Материал дополняет слайды L02. Практика выполняется в задачах, а HW02 начинается только от принятого `hw01-ready`.

## JSON, YAML и Python

Объект соответствует словарю, массив — списку, `null` — `None`. В YAML отступы задают вложенность, а кавычки могут менять тип: `hp: 10` — целое число, `hp: "10"` — строка.

Успешный разбор доказывает только синтаксис. Приложение отдельно проверяет версию, обязательные поля, точные типы, диапазоны и существование сцены.

Markdown записывает заголовки, списки, ссылки и фрагменты кода в обычном текстовом файле `.md`. Его используют для README и инструкций; [шпаргалка Markdown](https://cheatsheets.zip/markdown) помогает вспомнить обозначения. В отличие от JSON и YAML, здесь задача состоит в оформлении читаемого документа.

Учебный файл `student/lectures/examples/L02-EX01/lecture-state.json` показывает снимок партии: `schema_version`, `current_scene_id` и вложенный `player` с `name`, `hp`, `str`, `def`. Из каталога файла выполните `python -m json.tool lecture-state.json` и `python read_state.py`: первая команда проверяет синтаксис, вторая показывает, что `player.hp` после разбора имеет тип `int`. Строка `"10"` остаётся допустимым JSON, но не удовлетворяет контракту целочисленного `hp`.

Соседний `lecture-state.yaml` содержит исправленный YAML со слайда об отступах. Из каталога `student/lectures/` его можно разобрать командой `python -c "import yaml; print(yaml.safe_load(open('examples/L02-EX01/lecture-state.yaml', encoding='utf-8')))"` после подготовки окружения L02.

Из `student/lectures/examples/L02-EX01/` скопируйте файлы в `trial.json` и `trial.yaml` командами со слайдов. Измените `hp` на `11` в каждой копии и прочитайте оба значения командами Python: ожидаются две строки `11`. Затем добавьте лишнюю запятую после `"def": 2` в JSON и незакрытую скобку после `hp:` в YAML. Запишите ошибки разбора, исправьте файлы и повторите команды до двух успешных строк `11`.

## Сценарий и состояние партии

Сценарий содержит мир и переходы. Сохранение содержит только изменяемую партию:

```yaml
schema_version: 1
current_scene_id: SCN007
player:
  name: Мира
  hp: 6
  str: 3
  def: 2
```

В сохранение не входят весь сценарий, пароль и Bearer-токен.

## Безопасная загрузка

Порядок загрузки:

1. Прочитать текст во временную переменную;
2. Разобрать YAML;
3. Проверить версию;
4. Проверить поля и типы;
5. Проверить ссылку на сцену;
6. Создать новое состояние;
7. Присвоить его только после успеха.

Учебный EX01 проверяет только корневое отображение, версию `1`, целочисленный `hp` без `bool` и строковый ID сцены. `check.py` пробует версию `2`, корень `[]` и `hp: true` на том же объекте партии, затем подтверждает успешное применение. Проверка остальных полей, диапазонов, существования сцены и повреждённого файла входит в полный контракт HW02.

## Атомарная запись

Сначала создаётся временный файл рядом с целевым. После успешной записи и закрытия `os.replace` заменяет целевой путь. Ошибка до замены оставляет прежнее сохранение рабочим.

## AAA и TDD

Тестирование сопоставляет фактическое поведение программы с ожидаемым на выбранных данных. Это можно делать вручную либо повторяемым автоматическим тестом. Автоматический тест готовит известный вход, вызывает функцию и сравнивает результат с ожиданием. `unittest` находит методы с префиксом `test_` внутри класса `unittest.TestCase`. В EX04 вы увидите, как объявленная функция сначала вызывает `NotImplementedError`, а после минимальной реализации два теста проходят. В HW02 вы впервые добавите тесты к уже работающей предметной модели и получите красно-зелёный переход при создании хранилища.

AAA делит тест на Arrange, Act и Assert. Красный этап должен дойти до ещё не реализованной границы, зелёный — подтвердить минимальное поведение. Рефакторинг выполняется после зелёного результата с повтором тех же тестов.

В EX05 `pytest` собирает обычную функцию `test_choice`. Декоратор `@pytest.mark.parametrize` передаёт ей три набора аргументов и показывает результат каждого отдельно. Откройте `student/lectures/examples/L02-EX05/README.md`: временно испортите ожидание сценария `second`, наблюдайте одно падение, восстановите значение и получите три успешных сценария. HW02 пока использует `unittest` для тестов проекта.

Выполните:

```bash
python student/lectures/examples/L02-EX04/check.py
python student/lectures/examples/L02-EX01/check.py
python student/lectures/examples/L02-EX02/check.py
python student/lectures/examples/L02-EX03/check.py
python student/lectures/examples/L02-EX05/check.py
```

EX04 показывает базовое устройство теста для правила выбора сцены, EX01 — отказ без изменения партии, EX02 — красно-зелёный AAA-цикл, EX03 — диагностический и успешный Ruff, EX05 — три сценария pytest из одной функции.

## Трассировка и лог

Трассировку читайте снизу: тип и сообщение исключения, ближайшая строка собственного кода, одна проверяемая гипотеза. Ожидаемые ошибки сохранения превращаются в контролируемый `SaveGameError`; неожиданный дефект сохраняет трассировку.

Лог может содержать операцию, безопасное имя файла, код причины и идентификатор сцены после успеха. Полный YAML и секреты не журналируются.

### Подключение модуля logging

`logging` — модуль стандартной библиотеки Python; устанавливать его через pip не нужно. Инструкция `import logging` подключает модуль. `logging.getLogger("quest")` получает логгер — объект с именем `quest`, у которого вызывают методы `debug`, `info`, `warning` и `error`.

Перед первым сообщением настройте вывод через `logging.basicConfig`. В [console_demo.py](../lectures/examples/L02-EX06/console_demo.py) это сделано целиком, а [events.py](../lectures/examples/L02-EX06/events.py) показывает один ход. Логгер передаётся в `play_turn` как аргумент. Результаты вычислений попадают в лог только через явные вызовы, например `logger.info`: Python не журналирует их автоматически. `%s` внутри сообщения заменяется значением следующего аргумента.

Параметры настройки:

| Параметр | Назначение |
|---|---|
| `level` | Минимальный уровень сообщения; при `INFO` подробности `DEBUG` скрыты. |
| `format` | Вид записи: `%(levelname)s` — уровень, `%(name)s` — логгер, `%(message)s` — текст; `%(asctime)s` добавляет время. |
| `filename` | Путь файла; без него базовая настройка направляет сообщения в `stderr`, обычно видимый в терминале. |
| `encoding` | Кодировка файла; `utf-8` сохраняет русский текст. |
| `filemode` | Режим `a` дописывает записи, `w` стирает прежнее содержимое при запуске. |

Из каталога `student/lectures/` выполните:

```bash
python examples/L02-EX06/console_demo.py
```

Ожидается:

```text
INFO quest: Ход начат: scene_id=SCN007
INFO quest: Ход завершён: damage=2 hp=4
WARNING quest: Мало здоровья: hp=4
```

Вычисление уменьшило здоровье с `6` до `4`; вызов `logger.info` сохранил этот результат в сообщении. Подробность `DEBUG` скрыта порогом `INFO`. Чтобы увидеть её в терминале, замените в учебном `console_demo.py` порог на `logging.DEBUG` и запустите программу заново.

### Запись логов в файл

В [file_demo.py](../lectures/examples/L02-EX06/file_demo.py) задан порог `DEBUG`, путь `game.log`, кодировка `utf-8` и режим дополнения `a`. Из того же каталога выполните:

```bash
python examples/L02-EX06/file_demo.py
python -c "from pathlib import Path; print(Path('game.log').read_text(encoding='utf-8'), end='')"
```

После первого запуска файл содержит:

```text
DEBUG quest: Исходные данные: hp=6
INFO quest: Ход начат: scene_id=SCN007
INFO quest: Ход завершён: damage=2 hp=4
WARNING quest: Мало здоровья: hp=4
```

`game.log` создаётся в текущем каталоге запуска. При следующем запуске в конец добавятся ещё четыре записи. В терминал их выводит команда чтения файла; сам `file_demo.py` пишет только в файл. Лог событий не заменяет сохранение партии.

Вызывайте `basicConfig` один раз при запуске приложения. Если вывод уже настроен, обычный повторный вызов не изменит его. Поэтому два примера запускаются отдельными процессами Python. Автономная проверка `python examples/L02-EX06/check.py` проверяет фильтрацию `DEBUG`, переключение порога и сохранение записей двух запусков во временном каталоге.

Источник: [официальное руководство Python по logging](https://docs.python.org/3.14/howto/logging.html) (SRC80), необязательная справка.

## Ruff

Линтер проверяет статические правила, форматтер меняет механическое оформление. После автоматической правки нужно прочитать diff, повторить Ruff и запустить тесты. Зелёный Ruff не доказывает правильность поведения.

Из каталога `student/lectures/` запустите `python examples/L02-EX03/check.py`. Проверка сначала подтверждает диагностику `F401` для лишнего импорта, затем успешный запуск для исправленного кода. В HW02 настройте Ruff в своём `pyproject.toml` и после исправлений повторите проверку и тесты.
