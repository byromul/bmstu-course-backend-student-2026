# Конспект лекции 1 — Python, процесс, объект и первый тест

Лекция готовит к созданию `console-quest` из пустого каталога. Капсулы L01 дают автономные примеры, но не являются исходным кодом продукта.

## Команда и процесс

Терминал запускает программу с аргументами. Один запуск образует процесс со своей памятью, стандартным выводом, потоком ошибок и кодом завершения. Ноль обычно означает успех; ненулевой код требует прочитать первую причину и повторить проверку после исправления.

Относительный путь вычисляется от текущего каталога. Перед диагностикой «файл не найден» проверьте `Path.cwd()` и фактический путь команды.

## Среда Python

Курс использует Python 3.14.7. Виртуальное окружение принадлежит одному продукту и изолирует интерпретатор и зависимости. Для HW01 внешние пакеты не нужны, но `.venv` всё равно создаётся и исключается из Git.

## Минимум языка

Значение имеет тип; имя связывается со значением; выражение вычисляет новое значение. Список сохраняет порядок, словарь связывает ключи со значениями. Функция принимает аргументы и возвращает результат.

`input()` возвращает строку. Ожидаемый `ValueError` при преобразовании пользовательского значения обрабатывается у границы ввода; неожиданные исключения не скрываются общим `except Exception`.

## Модули и объекты

Модуль — файл Python. Обычный пакет содержит `__init__.py`, а `python -m client` запускает `client/__main__.py`. Предметные правила размещаются отдельно от `input()` и `print()`, чтобы тест мог вызвать их напрямую.

Класс задаёт общую форму, экземпляр хранит конкретное состояние. `self` получает тот экземпляр, через который вызван метод. `@dataclass(frozen=True)` помогает создать неизменяемую модель: переход возвращает новый объект, не меняя старый.

## Красный и зелёный тест

Сначала объявляется публичная функция с `NotImplementedError`, затем тест доходит до неё и даёт ожидаемый красный результат. После минимальной реализации тот же тест становится зелёным.

Ошибка импорта, неверный каталог или синтаксическая ошибка не являются содержательным красным этапом: тест ещё не достиг проверяемого правила.

## Локальный Git-цикл

Рабочее дерево содержит изменения, индекс — выбранный состав будущего коммита, коммит — сохранённый снимок локальной истории.

```bash
git status --short
git diff
git add <явные-пути>
git diff --staged
git commit -m "осмысленное сообщение"
git status --short
```

Для HW01 удалённый репозиторий не нужен. При расхождении истории сохраните вывод и запросите разбор; не выполняйте принудительный push или массовый сброс.

## Автономные капсулы

Из `student/lectures/capsules/L01/` выполните:

```bash

```

CAP01 показывает независимость двух объектов, CAP02 — базовые конструкции, CAP03 — импорт и класс, CAP04 — красно-зелёный переход. Ни одна капсула не создаёт `console-quest`.

## Самопроверка

До просмотра разбора ответьте:

1. Почему изменение первого объекта CAP01 не меняет второй;
2. какое действие следует после сообщения preflight о ненастроенном `user.email`;
3. что безопасно сделать после остановки `git pull --ff-only` из-за расходящихся историй.

Сверьте причинную цепочку со слайдами, а не только конечные слова.

## Переход к HW01

HW01 начинается командами `mkdir console-quest` и `git init -b main`. Затем студент создаёт `.venv`, точное дерево пакета, публичный интерфейс, открытые тесты и собственную реализацию. Готовность подтверждают два финала, восстановление после неверного ввода, внешний проверяющий инструмент, чистый коммит и тег `hw01-ready`.
