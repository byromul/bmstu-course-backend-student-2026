# Конспект лекции 1 — терминал, Python, объекты и Git

Лекция готовит к созданию `console-quest` с нуля. Задачи L01 дают автономные примеры, но не являются исходным кодом проекта.

`console-quest` станет первым самостоятельным проектом с консольным клиентом. Во втором блоке курс создаст отдельный `django-quest` с серверной частью на Django и JSON API.

## Команда и процесс

Терминал — один из основных рабочих инструментов программиста: через него запускают интерпретатор, тесты, Git и служебные программы. Терминал запускает программу с аргументами, а один запуск образует процесс со своей памятью, стандартным выводом, потоком ошибок и кодом завершения.

В Bash и Zsh `Tab` дополняет команду или путь, стрелки вверх и вниз листают историю, `Ctrl+R` ищет по фрагменту старой команды, `history` выводит историю, а `Ctrl+C` посылает прерывание текущему процессу. Не вводите секреты в командную строку: история может сохранить их. Для долгой истории Bash задайте в `~/.bashrc` `export HISTSIZE=1000000`, `export HISTFILESIZE=1000000` и `shopt -s histappend`; в Zsh используйте `HISTSIZE`, `SAVEHIST` и `HISTFILE` в `~/.zshrc`.

В Linux и macOS `ps -ef` показывает снимок процессов, а `top` обновляет сведения о нагрузке до выхода клавишей `q`. В PowerShell список процессов получают через `Get-Process`.

На условной сортировочной линии подробное сообщение предназначено человеку, а следующему автомату нужен однозначный сигнал «продолжать» или «остановиться». Код завершения выполняет ту же роль между программами. Ноль обычно означает успех; ненулевой код требует прочитать первую причину и повторить проверку после исправления.

Относительный путь вычисляется от текущего каталога. Перед диагностикой «файл не найден» проверьте `Path.cwd()` и фактический путь команды.

## Среда Python

Python развивается и выпускает новые версии, в которых появляются новые возможности. Номер версии точно называет возможности используемого интерпретатора. Курс фиксирует Python 3.14.7, чтобы команды и поведение примеров имели общую исходную среду. Виртуальное окружение принадлежит одному проекту и изолирует интерпретатор и зависимости. Для HW01 внешние пакеты не нужны, но `.venv` всё равно создаётся и исключается из Git.

## Минимум языка

Значение имеет тип; имя связывается со значением; выражение вычисляет новое значение. Список сохраняет порядок, словарь связывает ключи со значениями. Функция принимает аргументы и возвращает результат.

`input()` возвращает строку. Ожидаемый `ValueError` при преобразовании пользовательского значения обрабатывается у границы ввода; неожиданные исключения не скрываются общим `except Exception`.

## Модули и объекты

Модуль — файл Python. Обычный пакет содержит `__init__.py`, а `python -m client` запускает `client/__main__.py`. Предметные правила размещаются отдельно от `input()` и `print()`, чтобы другие модули могли вызвать их напрямую.

Класс задаёт структуру будущих объектов, а экземпляр (объект) хранит конкретное состояние. `self` получает тот объект, через который вызван метод. `@dataclass(frozen=True)` помогает создать неизменяемую модель: переход возвращает новый объект, не меняя старый.

## Локальный Git-цикл

Рабочее дерево содержит изменения, индекс — выбранный состав будущего коммита, коммит — сохранённый снимок локальной истории. Каждый коммит получает вычисленный по его содержимому хеш и содержит хеш родительского коммита.

`git init -b main` создаёт скрытый `.git` в текущем каталоге. В нём `HEAD` указывает на ветку, `config` хранит настройки, `objects/` — объекты истории, `refs/heads/` — ссылки на ветки, `refs/tags/` — ссылки на теги. Детали служебного дерева меняются между версиями Git; меняйте историю командами Git.

```bash
git status --short
git diff
git add <явные-пути>
git diff --staged
git commit -m "осмысленное сообщение"
git tag hw01-ready
git show --no-patch --oneline hw01-ready
git status --short
```

Тег Git — осмысленное имя выбранного коммита, которое Git не передвигает автоматически при появлении новых коммитов. В HW01 тег `hw01-ready` отмечает проверенный финальный коммит; после внешней проверки студент отправляет ветку `main` и этот тег в собственный пустой репозиторий GitHub.

При линейном продолжении `git pull --ff-only` передвигает имя ветки вперёд без нового коммита. При расхождении флаг сохраняет граф без изменения и останавливает команду; обычный `pull` при настроенной стратегии слияния может вместо этого создать дополнительный коммит с двумя родителями. Сохраните вывод и запросите разбор; не выполняйте принудительный push или массовый сброс.

## Самопроверка

До просмотра разбора ответьте:

1. Почему изменение первого объекта EX01 не меняет второй;
2. Какое действие следует после сообщения preflight о ненастроенном `user.email`;
3. Что безопасно сделать после остановки `git pull --ff-only` из-за расходящихся историй.

Сверьте причинную цепочку со слайдами, а не только конечные слова.

## Переход к HW01

HW01 начинается командами `mkdir console-quest` и `git init -b main`. Затем студент создаёт `.venv`, точное дерево пакета и по последовательным копируемым блокам развивает сценарий, состояние партии, переход и консольный цикл; каждый этап можно сначала выполнить самостоятельно и проверить по готовому примеру. Готовность подтверждают два финала, восстановление после неверного ввода, внешняя проверка, чистый коммит и совпадающие с ним удалённые ветка `main` и тег `hw01-ready` на GitHub. Первые автоматические тесты продукта появятся после лекции 2.
