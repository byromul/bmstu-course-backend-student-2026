# Конспект лекции 1 — терминал, Python, объекты и Git

Лекция готовит к созданию `console-quest` с нуля. Задачи L01 дают автономные примеры, но не являются исходным кодом проекта.

`console-quest` станет первым самостоятельным проектом с консольным клиентом. Во втором блоке курс создаст отдельный `django-quest` с серверной частью на Django и JSON API.

## Команда и процесс

Терминал — один из основных рабочих инструментов программиста: через него запускают интерпретатор, тесты, Git и служебные программы. Все команды и демонстрации L01 рассчитаны на Linux и Bash. Терминал передаёт введённую строку оболочке Bash; она разбирает команду и запускает программу с аргументами. Один запуск образует процесс со своей памятью, стандартным выводом, потоком ошибок и кодом завершения.

В Bash `Tab` дополняет команду или путь, стрелки вверх и вниз листают историю, `Ctrl+R` ищет по фрагменту старой команды, `history` выводит историю, а `Ctrl+C` посылает прерывание текущему процессу. Не вводите секреты в командную строку: история может сохранить их. Для долгой истории Bash задайте в `~/.bashrc` `export HISTSIZE=1000000`, `export HISTFILESIZE=1000000` и `shopt -s histappend`.

В Linux `ps -ef` показывает снимок процессов, а `top` обновляет сведения о нагрузке до выхода клавишей `q`.

На условной сортировочной линии подробное сообщение предназначено человеку, а следующему автомату нужен однозначный сигнал «продолжать» или «остановиться». Код завершения выполняет ту же роль между программами. Ноль обычно означает успех; ненулевой код требует прочитать первую причину и повторить проверку после исправления.

Относительный путь вычисляется от текущего каталога. Перед диагностикой «файл не найден» проверьте `Path.cwd()` и фактический путь команды.

## Минимум языка

Значение имеет тип; имя связывается со значением; выражение вычисляет новое значение. В примере лекции `next_scene_id = None` означает финал: следующей сцены нет. Список сохраняет порядок, словарь связывает ключи со значениями. Функция принимает аргументы и возвращает результат.

`input()` возвращает строку. Ожидаемый `ValueError` при преобразовании пользовательского значения обрабатывается у границы ввода; неожиданные исключения не скрываются общим `except Exception`.

## Модули и объекты

Модуль — файл Python. В EX02 `invalid_case.py` импортирует знакомую функцию `parse_choice` из `control_flow.py` и вызывает её. Предметные правила размещаются отдельно от `input()` и `print()`, чтобы другие модули могли вызвать их напрямую.

Класс задаёт структуру будущих объектов, а экземпляр хранит конкретное состояние. Вызов `GameState("START")` создаёт экземпляр и вызывает `__init__` для начальной настройки. Параметр `self` получает этот экземпляр; присваивание `self.current_scene_id = current_scene_id` записывает переданную строку в его атрибут.

В EX01 два вызова класса создают независимые состояния. В контрпримере `shared_state.py` присваивание `second = first` связывает оба имени с одним объектом, поэтому изменение атрибута видно через оба имени: вывод будет `END`, затем `END`.

В EX03 `scene.py` объявляет класс `Scene`, а `use_scene.py` импортирует его и создаёт экземпляр. `@dataclass` создаёт служебные методы по полям. `frozen=True` запрещает обычное присваивание полям существующего экземпляра, но не делает вложенные изменяемые объекты неизменяемыми.

Связанные модули объединяют в пакет. Обычный пакет содержит `__init__.py`, а `python -m client` запускает `client/__main__.py`.

## Среда Python

Python развивается и выпускает новые версии, в которых появляются новые возможности. Номер версии точно называет возможности используемого интерпретатора. Курс фиксирует Python 3.14.7, чтобы команды и поведение примеров имели общую исходную среду. Виртуальное окружение принадлежит одному проекту и изолирует интерпретатор и зависимости. Для HW01 внешние пакеты не нужны, но `.venv` всё равно создаётся и исключается из Git.

## Локальный Git-цикл

Рабочее дерево содержит текущие файлы, индекс — подготовленное дерево следующего коммита. Коммит сохраняет всё дерево из индекса, включая уже отслеживаемые файлы без новых изменений. Неподготовленная правка остаётся в рабочем дереве; новый неотслеживаемый файл не попадёт в снимок до `git add`. Коммит получает вычисленный по содержимому хеш и ссылки на родительские коммиты; у первого коммита родителей нет.

`git init -b main` создаёт скрытый `.git` в текущем каталоге. В нём `HEAD` указывает на ветку, `config` хранит настройки, `objects/` — объекты истории, `refs/heads/` — ссылки на ветки, `refs/tags/` — ссылки на теги. Детали служебного дерева меняются между версиями Git; меняйте историю командами Git.

В лекционной демонстрации создаётся временный репозиторий с одним файлом. После настройки автора выполните:

```bash
demo_dir=$(mktemp -d)
cd "$demo_dir"
git init -b main
printf 'print("START")\n' > example.py
python example.py
git status --short
git add example.py
git diff --staged
git commit -m "Добавить начальную сцену"
git tag demo-ready
```

Программа печатает `START`. До `add` файл показан как `?? example.py`, после добавления в индексе находится его содержимое. Сохраните второе изменение в отдельной ветке и включите его в `main`:

```bash
git switch -c feature/choice
printf 'print("END")\n' > example.py
python example.py
git diff
git add example.py
git diff --staged
git commit -m "Показать финальную сцену"
git switch main
git merge feature/choice
python example.py
git log --oneline --graph --decorate --all
git status --short
```

Оба запуска изменённой программы печатают `END`. В истории два коммита, `main` и `feature/choice` указывают на второй, `demo-ready` остаётся на первом. Финальный `status --short` пуст.

Тег Git — осмысленное имя выбранного коммита, которое Git не передвигает автоматически при появлении новых коммитов. В HW01 тег `hw01-ready` отмечает проверенный финальный коммит; после внешней проверки студент отправляет ветку `main` и этот тег в собственный пустой репозиторий GitHub.

Сетевые команды из лекции требуют настроенного `origin`, доступа и связи текущей ветки с удалённой; в локальном примере их не выполняют. При линейном продолжении `git pull --ff-only` передвигает имя ветки вперёд без нового коммита. При расхождении флаг останавливает интеграцию, сохраняя текущую локальную ветку; получение данных при этом уже могло обновить ссылки удалённых веток и добавить коммиты; обычный `pull` при настроенной стратегии слияния может вместо этого создать дополнительный коммит с двумя родителями. Сохраните вывод и запросите разбор; не выполняйте принудительный push или массовый сброс.
